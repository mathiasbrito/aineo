# 2026-10-18 — T93 Zoom

**Author:** the repository's maintainer, with Claude — implementer agent (`neovim-lua-developer`, on Sonnet)
**Branch:** `feature/t93-zoom` · **Pull request:** #276 (into `dev`)

`\z` zooms the window of the right column the cursor is in to the column's whole height, under every pane, and gives the heights back when pressed again. A feature of the user's prompt-driven waves (D26 applies).

## Design

- **Where it lives.** The heights of the right column's windows already live in `aineo.layout` (`size_right_column()`, `equalize_run_windows()`, `keep_proportions()`), and so does every event that changes the column, so the zoom is the layout's state: `lua/aineo/layout/zoom.lua` holds the mechanics (`start()`, `keep()`, `restore()`; no state, no aineo module) and `layout/init.lua` holds `state.zoom` and one public function, `toggle_zoom()`. A separate `aineo.zoom` home would need a row in the modularity skill's table (an `ai/` change) for a concern that is the layout's own state; rejected. `entry/` only wires: `ACTIONS.zoom` in `actions.lua` acts on the aineo tab of the current tab page (`tab.actions.zoom` → `homes.layout.toggle_zoom()`) and makes none; from a tab page that is none of aineo's it calls the module's own layout, whose column the cursor is not in, so it tells the user.
- **The mechanics (after the fix round).** The zoomed window is asked for its own rows plus the rows each other window of the column can spare, `winheight()` less `'winminheight'` (`take_rows()`), so Neovim shrinks the others to `'winminheight'` lines (one by default, none at 0; the winbar of a run pane window besides — `nvim_win_set_height()` counts the winbar, so such a window is two rows) and never reaches a window outside the column. The version of the first push asked for `vim.o.lines` rows and let Neovim take them; the attack review found that it then took rows from a window across the whole width below the layout (see the fix round). Before that, a loop shrank the others first; two mutants (the loop deleted, the one line set to two) survived it, so the loop went. `restore()` sets each window but the last from the top to the height recorded when the zoom began (`nvim_win_get_height()`), the last taking what remains; when the windows hold other rows together than when the zoom began, the recorded heights are scaled to the rows held now and rounded (A500).
- **What ends it.** `column_windows()` is the right column's windows under the pane shown (the run pane's stack, or the Report's window and Input's), and a zoom is "of the column" while that list equals the one recorded (`is_zoom_of_column()`).
  - `switch_pane()` calls `end_zoom()` after its early return for the pane shown, so asking for the pane shown keeps the zoom (M18) and any switch gives the heights back first.
  - `sync_run_windows()` ends it, heights given back, when the stack the terminals ask for is not the one the windows show (`run_stack_shows()`), before it opens a window below a one-line window or closes one; and `equalize_run_windows()` leaves a zoomed stack alone.
  - A closed window (`WinClosed` → `keep_proportions()` → `apply_proportions()`) finds the column changed (`keep_zoom()`), drops the zoom without restoring (the neighbours took the rows already) and the layout's proportions apply as for any closed window.
  - `end_zoom()` restores only while the column is the one zoomed, and `toggle_zoom()` counts a zoom only while it is of the column: a layout whose windows closed with `is_open()` false (no proportions step ran) holds a stale zoom, which raised "Invalid window id" and then unzoomed instead of zooming (red, then M7, M8).
  - A resize of the editor and `TabEnter` land in `apply_proportions()`, where `keep_zoom()` zooms the same window again in place of the right column's proportions.
- **Cursor.** No handler: the cursor moving changes nothing (M17); `\z` in another window of the column ends the first zoom (heights back) and starts one in the new window, so the heights a later `\z` gives back are those before the first zoom (pinned).
- **Outside the column** the layout tells the user once, as a warning, and changes nothing; the terminal pane's one window is a column of one window and `\z` there changes no height and tells nothing (M20).
- **Keys.** `zoom` → `z`; `:Aineo` completion, usage and `desc`, the `<Plug>` mapping, the prefix key, the terminal prefix twin and the health check's key list follow from the tables, as `find` did.

## Measured (Neovim 0.12.5, headless)

- `nvim_win_set_height(window, 1)` on a window with a winbar gives `nvim_win_get_height()` 2 (`winheight()` 1): the winbar counts. A column of three run pane windows zoomed in the middle is 1 + the rest + 1 text lines, each other window two rows with its winbar.
- Asked for more rows than the screen has, a window takes every row the others can spare: windows with `'winfixheight'` (the Report and Input) shrink too; none raised an error or an E36.
- `'winminheight'` above one (set with `'winheight'`, since `'winheight'` may not be smaller): the other windows keep that height without an error and the zoomed window takes the rest.
- Splitting a one-line window with `nvim_open_win()` worked in the run pane, but the zoom ends before it, so the new window shares the column.
- A restore after the editor was resized sets each window but the last to the recorded height; the last takes what remains (documented in the help).

## Limits and open threads

- The zoom knows the windows the layout knows (the Report's, Input's, the run pane's). A window the user splits off the zoomed one by hand (`:split`) is not in the column's list, so it changes neither the zoom nor its end, `\z` there warns, and the help says so (A492).
- A resize of the editor keeps the zoom; the heights a later `\z` gives back are those recorded, scaled to the rows the column holds then (A500). `<C-w>=` while the run pane is zoomed equalizes it on screen and leaves the zoom on (documented).
