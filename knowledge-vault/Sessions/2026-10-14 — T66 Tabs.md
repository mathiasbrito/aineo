## What was done

- **`plugin/aineo.lua`.** The per-session state and functions of the file (`panes_session`, `claimed`, `claimed_by_id`, `start_confirmed`, `claude_terminal`, `session_read_in_flight`, the follows, the claims, the start, the layout's opening, the switch and the join) became `make_tab(homes, key, on_bound)`, a tab over the five homes it is given. Above it the file holds what the editor shares: `tab_list`, `last_used_tab`, the handlers of `aineo.editors` (`FocusGained`, `TabEnter`, `VimLeavePre`, the switch told by another editor), `new_tab()`, `route_report()`, `acting_tab()`, `hold_tab()`, `close_tab()` and the `TabClosed` handler, `open_new_tab()`, `jump_to_tab()` and `claim_in_current_tab()`.
- **The first tab** is made of the homes the modules themselves are (`require('aineo.layout')` and the others), so every caller and suite of today stands; every tab after it of the `new()` copies, keyed `2`, `3`… by the order tabs were made. The first tab writes its entry with no `tab`, as today.
- **Keys and commands.** `:Aineo tab new` (`<Plug>(aineo-tab-new)`, `\T`, `<C-\>T`), `:Aineo tab {n}` for any n and `<Plug>(aineo-tab-1)` … `(aineo-tab-9)`, `\1` … `\9` and their twins; completion offers `new` and each tab page's number; any other word is refused with one error.
- **Routing.** The report home's router (`set_report_router`) is given at the first tab: a report goes to the tab whose Claude Code has the offer's token and whose panes follow its session, else a tab whose panes follow the session, else, offered `at_start`, the tab whose Claude Code has the token; a report of no known session goes to the token's tab (A293). An action acts on the tab whose tab page is current, or on the aineo tab used last, moving there; `:Aineo claim {id}` acts in the current tab, or moves to the tab that runs the session.
- **Entries.** Each tab writes its own entry, keyed by the tab; the entered tab's entry is written again at `TabEnter` (it is marked used); quitting removes every entry of the editor.
- **Closing.** A tab page that Neovim closes is found at `TabClosed` (`aineo.tabs`' `closed()`): the tab leaves `tab_list` first, its entry comes off the list, its claim is let go, its draft saved, and its layout, changes pane and Report let go (`release()`). Its Claude Code is stopped once the command has ended, together with those of the other tab pages the command closed (`finish_closing()`, `aineo.claude`'s `stop_sessions()`); then its terminal is wiped and its Claude home let go (`finish()`). The first tab leaves its homes, its terminal included, as they are, and is the tab the next tab opened is made of, taken up again with nothing of what it held (`reopen()`).
- **Titles.** The tabs home holds each aineo tab with the session's name; aineo's tab line is drawn while `'tabline'` is empty; a dictionary watcher on `b:aineo_session_name` of each Claude terminal has `:redrawtabline` run when the name changes; `require('aineo').tab_title(n)` gives a title.
- **Homes (A258, A293).** `let_go()` on the claude, report, draft and changes copies; the report copy takes a report of no known session when `options.at_start`. Their tests are in the copies' own suites.
- **Health and help.** `:checkhealth aineo` lists `\T`, `\1`–`\9` and their twins and gains a *Tab line* section; the help gains *Tabs*, `:Aineo-tab`, the `<Plug>` and key entries, the health lines and *Several tabs* in the limits.

## Decisions and spec conflicts

- **The first tab's homes after it closes (A261).** Reused, not retired. The amendment said retired; four pins of the entry suites (the exited terminal reshown by `:Aineo report` after `:tabonly`, the hidden line numbers kept after `1tabclose`, the layout's buffer names) stand on reuse, and the homes' module copies cannot be let go anyway. Recorded in the correction to the brief's amendment.
- **O8 against the brief's item 1.** O8 has every tab start in the folder; item 1 has every entry suite of today pass unchanged. A single-tab Neovim that does `:cd` and restarts Claude Code resumes that directory's own session, and four suites pin it (`test_entry_claude_name`, `test_entry_claude_resume`, `test_entry_session_handover` ×2, `test_entry_session_switch`). The first tab keeps `getcwd()`, every tab after it starts in `places.working_directory`. Ruled on 2026-10-15, A298 (the orchestrator's assumption): so it stands, the existing pins with it.
- **O6, rule 3.** The token's tab takes an `at_start` offer whatever its panes follow; its home decides. `test_entry_claim`'s case of a report kept with the directory's records while a claim holds the panes elsewhere needs it. A300.
- **The first tab's entry has no key.** The entry suites read the file by the address alone.
- **The edge `aineo` → `aineo.tabs`** (`tab_title()`'s lazy require) is not in the modularity skill's direction table, nor is `aineo.tabs` in its module table. A301: accepted; the table gets it in the `ai/` change after wave 16.
- **The boundary** was widened, as the dispatch and A258 state, to `lua/aineo/report/` (A293's rule) and the four homes' `let_go()`; `tests/helpers/entry.lua`'s `USAGE` was edited, not added to, since it pins the subcommands' list: a helper pin that moved.
- **`plugin/aineo.lua` is now about 2500 lines.** The brief's boundary kept the per-tab composition in the composition root. A home of its own would be the modular shape; A303 defers it to a `refactor/` packet after wave 16.
- **The 66 entry cases** stand (A302).
- **A commit message of the packet is wrong.** The body of `c2bb906` says the composition root retires the module's homes with the first tab (A261). It reuses them; the correction to the brief and this note say so, and the pushed history is not rewritten.

## Fix round

Rulings A298–A307 are in the brief's correction. Each fix was seen failing first (the cases marked *fix round* above).

- **The reused first tab starts clean (attacks 1, 2; tests 2).** `reopen()` forgets the closed tab's claim, panes' session, start confirmation and warnings, and the tab starts in the folder (`is_reopened`); `start_in_new_tab()` makes its panes follow the new id at once, so Input does not keep the closed session's draft, and shows the agent pane.
- **A closed tab writes nothing (attack 5; tests 1).** `is_released` is set by `release()`, honoured by `write_entry()` and `claim()`, and cleared by `reopen()`. M11 was reachable.
- **A305.** `TabClosed` only releases the tab: its claim, draft, layout, changes pane and Report, its entry. The stop is deferred (`vim.schedule(finish_closing)`) and stops every tab the command closed with one `stop_sessions()`. `new_tab()` runs it first, and is refused while it runs (`is_stopping`), so the first tab is not given a Claude Code that has not stopped; a command that opens a tab while the stop runs gets `aineo: the Claude Code of a closed tab is still stopping; try again in a moment`. `:Aineo tab new` retried until it opens is how the cases wait (F12 removes the refusal).
- **A304.** The report home's declining a report of no known session is final: `RECEIVE_REPORT` returns its answer, and `deliver_report()` answers `failed` with `no tab of the editor runs the Claude Code that sent the report`. The T64 pin that expected the fallback moved.
- **Attack 6.** Visual Send from a tab page that is not aineo's gets Send's own warning and the cursor stays.
- **Attack 7.** `aineo.changes.pause` has a `close()`, called by the changes copy's `let_go()`.
- **A307.** `:Aineo tab {n}` warns with the number as typed.
- **Records.** The commit message mistake, the P2 row, the mutant numbers, the case table and the unmarked task line, as the reviews asked; "smallest" and `on_bound`'s doc; the *Tabs* help; the orphan docstring line in `changes/copy.lua`.
