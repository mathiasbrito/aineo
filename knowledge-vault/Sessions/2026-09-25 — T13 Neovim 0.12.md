## What was done

- **`plugin/aineo.lua`** (NC2, MR64): `ERROR_FRAMING` strips `^Lua: `, the words 0.12 wraps an error raised in Lua in, before `^Error executing lua: `. On 0.12.5 the user is told `aineo: nvim_exec2()[1]..TermOpen Autocommands for "*": Vim(append):Lua callback: [string "<nvim>"]:3: the user autocommand fails`. The inner `Lua callback:` differs from 0.11's `Error executing lua callback:`. It is not framing at the line's start, so it stays, and the test states each version's text.
- **`lua/aineo/mcp/editor.lua`** (NC3, C5): `first_line()` became `editor_reason()`. It strips `^Lua: ` and `^Error executing lua: ` from the editor's error, so Claude's tool error reads `the editor did not take the report: aineo.report has no environment: call set_report_environment() first` on both versions.
- **`lua/aineo/health.lua`** (NC4, C7): `error_line()` strips two position forms. One is `<file>.lua:<n>: `. The other is `vim/<module>:<n>: `, which 0.12 uses for its own Lua because those modules are named without `.lua`. The "could not run" warning reads `ENOENT: no such file or directory` on both versions. The configuration error shares the function, and its pins stay green.
- **`tests/test_claude.lua`** (NC5, C3): the exit-line case reads `[Process exited 3]` where each version puts it:
  - on 0.11, the buffer's text, through `claude.wait_for_screen`;
  - from 0.12 on, the virtual text of the extmark in the `nvim.terminal.exitmsg` namespace, set by the default `TermClose` autocommand of group `nvim.terminal`. This check is written inline in the test file; `tests/helpers/claude_session.lua` is unchanged.
  - The `start_session()` error pin states each version's request framing.
  - `lua/aineo/claude/` is unchanged.
- **`tests/helpers/report_tui.lua`** (NC6):
  - The helper waits for `v:vim_did_enter` before its first request that loads aineo.
  - It answers the TUI's Device Status Report query (`CSI 5 n` → `CSI 0 n`), as a terminal would. 0.12's startup therefore no longer waits 100 ms and leaves E1568 in `:messages`.
  - `tests/test_mcp_blocked_editor.lua` gains two cases: the editor loads aineo's report home as it starts, and it starts with no message.
- **`tests/test_entry.lua`, `tests/test_mcp_delivery.lua`**: each states the text on both versions. The delivery text has no framing on either.
- **`doc/aineo.txt`**, inside `*aineo-install*` only: aineo's behaviour was measured on Neovim 0.11.6 and 0.12.5.

## Measurements this rests on

- **The exit line** (`t13-exitline-probe.lua`, `nvim --clean --headless -l`, a terminal running `sh -c 'exit 3'`):
  - 0.12.5: the buffer text does not hold `[Process exited 3]`; one extmark in `nvim.terminal.exitmsg` has that virtual text.
  - 0.11.6: the buffer text holds it, and there is no such namespace.
  - This confirms the brief review's reading.
- **Where 0.12's runtime Lua puts its position** (`t13-position-probe.lua`, the first line of `pcall`'s error on each version):

  | call | 0.11.6 | 0.12.5 |
  |---|---|---|
  | `vim.system({'/nonexistent/…'})` | `…/runtime/lua/vim/_system.lua:254: ENOENT: …` | `vim/_core/system:324: ENOENT: …` |
  | `vim.split(nil, ',')` | `vim/shared.lua:0: s: expected string, got nil` | `vim/_core/shared:137: s: expected string, got nil` |
  | `vim.keymap.set('n', 1, 2)` | `vim/keymap.lua:0: lhs: expected string, got number` | `[string "vim/keymap"]:59: lhs: expected string, got number` |
  | `vim.validate('opts', 1, 'table')` from a file | `<file>.lua:2: opts: …` | `<file>.lua:2: opts: …` |

  - **Does `plugin/aineo.lua`'s `'^.-%.lua:%d+: '` meet 0.12's shape? No.** It meets neither `vim/_core/<m>:<n>: ` nor `[string "vim/<m>"]:<n>: `.
  - No action is known to raise from Neovim's runtime Lua. `vim.validate`'s position is its caller's, a `.lua` file, on both versions. The suite shows none, so no pattern was added there (see *Open threads*).
  - `health.lua`'s new form covers `vim/_core/…`, not the `[string "vim/…"]` form.
- **0.12's startup wait** (NC6): 0.12.5's `vim/_core/defaults.lua` sends OSC 11 and DSR, then runs `vim.wait(100, …)` until the DSR answer arrives. It warns with E1568 unless `NVIM_TEST` is set.
  - Answering the DSR is not enough on its own. With the answer in place and the VimEnter wait removed (mutant M11), all 5 cases still fail on 0.12.5 with `module 'aineo.report' not found`. The first request is still served during startup, so both changes are needed.

## Decisions & reasoning

- **The helper answers the DSR query rather than setting `NVIM_TEST`.** `NVIM_TEST` would hide E1568 and keep the wait it reports. It is also a switch no user's editor has, and this test file is about what a user's editor shows.
- **Both framings are stripped on either version, in `plugin/aineo.lua` and in the relay.** C5's relay runs on the editor's `v:progpath`, so relay and editor are normally one version. Stripping both avoids a version check in production code. As a result, a mutant that drops one version's framing survives on the other version, and it is recorded so (below).
- **The version branches live in the test files' constants and helpers**, never inside a case: `vim.fn.has('nvim-0.12')` picks the whole expected text. No pattern was widened to accept both.
- **A query split across two reads is not joined.** The first answerer joined one, but its mutant survived because no run split a query. Under YAGNI the join was removed in the second commit.
