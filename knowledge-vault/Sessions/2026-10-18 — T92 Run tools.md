## Design

- **Three layers for "only when the user asks".** The instructions aineo appends to Claude Code's system prompt (`mcp.run_instructions()`) and the descriptions of `run` and `run_stop` say so; `run` and `run_stop` are not in `--allowedTools`, so Claude Code asks the user for each call and shows the command (the hard gate: instructions cannot guarantee intent); a call no tab runs is not taken. Only `run_output`, which changes nothing, joins `report` and `announce_work` in `mcp.allowed_mcp_tools()` (D87 amends D11's list).
- **The relay side, `lua/aineo/mcp/`.** `run_tools.lua` holds the three tool descriptions and `validate(tool, arguments)`, a table of fields by tool and kinds (`command`, `label`, `text`, `flag`, `count`): a JSON null in an optional field counts as not given, a NUL or a control character (in a name or directory) and an unknown field are refused, the reason naming the field. `protocol.lua` dispatches a valid call to `deliverers.run_call`; `run_calls.lua` offers it to the editor that started Claude Code (`editor.offer_report()` now returns what the editor answered and takes a `subject`, so that a refusal or an unconfirmed call says “call” where a report says “report”), and turns the answer into words: `not taken: …` for a call no tab took, the editor's words otherwise. `mcp.on_run_called()` / `receive_run_call()` are the editor's end, bound once by the composition root, as for an announcement.
- **The editor side, `lua/aineo/entry/`.** `editors.lua` routes a call by its start token (`routing.tab_for_work()`, the tab whose Claude Code holds it) and hands the tab, the project folder and a teller to `run_tools.call()`. `run_tools.lua` is the three handlers, with the dependencies as parameters: `run` resolves `directory` (relative to the folder; real path; accepted only when it is the folder or a worktree from `git worktree list`, which is asked for, with `vim.wait`, only when a directory other than the folder is given), makes the name unused (`sleep`, `sleep-2`), starts through `tab.start_in_run_stack()` and tells the user once; `run_output` and `run_stop` find the process by name (none: the names there are; two: refused, not guessed). `run_pane.start_in_stack()` starts without showing the pane (A476), refreshes a stack that is shown in the current tab page, and makes the quit guard.
- **The run home, `lua/aineo/run/`.** `settings.name`, `entries()` (copies of buffer, name, status), and `read_output(buffer, query)` over `output.lua`'s `select(lines, query)`: the terminal's rows without the empty padding; the lines after `after_line` matching `pattern` (a Vim regex, `\v` and `\c` or `\C` put in front) and not `exclude`; the last `last` of them (40 by default, no maximum); `context` lines around each, once where they overlap, clamped to the output and to `after_line`; the number left out; the state. A regex that does not parse is answered with the editor's error naming the field. The answer's text (`entry/run_tools.lua`) is a header with the state and the total lines, which is the `after_line` to follow from, then `12: text` for a match and `13- text` for context, `--` between gaps.
- **Measured here (Neovim 0.12.5).** `vim.regex` with `\v\c` prefixed keeps `^`, `$`, counts, alternation and `(x)@=` working, and a regex that does not parse raises `couldn't parse regex: Vim:E54: …`. A terminal buffer with `'scrollback'` 100 and 300 lines printed held 122 rows, the first `row 180`: rows shift once the output outgrows it. Vim's regex engine has no time limit of its own; the first version matched with `vim.regex`, and the fix round bounds the matching with `search()` and a timeout (below).

## Fix round (PR #275, the attack and records reviews)

The orchestrator's rulings, A490 and A491 revised and A496–A499, are in the D85/D87 rows as the orchestrator's.

- **A496 (attack F1, high).** The gate D85 rests on did not hold: since Claude Code 2.1.283 an interactive session starts in auto mode, where a classifier approves an unmarked MCP tool, and one “don't ask again” removes the prompt for good. `run` and `run_stop` now carry `_meta["anthropic/requiresUserInteraction"] = true` in `tools/list` (the reviewer's measured diff), so Claude Code asks for every call in every mode, offers no “don't ask again”, is not skipped by an allow rule, and denies the call in `dontAsk`. Read from Claude Code 2.1.302's program, not run. Pinned through the relay's `tools/list`; `run_output` carries none.
- **A490 revised (F4).** `run_output` refuses the interactive `\X` shell (`entries()` carries `is_interactive_shell`); a command started by `\x` or `run` is read, an interactive program included, and the help says so.
- **A491 revised (F5).** `(a+)+\1x` over 2000 rows held the editor for more than five minutes. The matching is now `search()` with a timeout in a scratch buffer, 2000 ms for the whole call (measured: three row shapes of 80, 200 and 200 columns ended at 2000 ms with the error; `(.*)(.*)(.*)(.*)(.*)x` ended in 170 ms; no `:messages` entry and no blocking prompt after a stop). The bound hit, or the engine giving up on memory (E363), is answered with `pattern: matching took longer than 2000 ms and was stopped; try a simpler pattern`. `last`, `context` and line counts stay unlimited (D87).
- **A497 (F2).** The description, the instructions and the help list `= @ % & ~ {` as operators of very magic that must be escaped, with `<` `>` as word boundaries, and drop “work as in most regex flavours”. Cases for `level\=error` and `\~/x`.
- **A498 (F3).** Lines are terminal rows. A resize of the pane or the `'scrollback'` limit renumbers them; `after_line` past the last line is answered with a note to read again without it. No cheap detection of the pane's width was built. D87's “no line cut” reads “aineo cuts no line; the terminal wraps rows”.
- **F6.** A line `exclude` drops is never read, not even as context. **A499 (F7, F8).** The default name loses its control characters (`command` when nothing is left); `command` refuses the C0 control characters but tab and line feed.
- **Records.** Cases for `last` 250, `context` 9 and a 700-character line (the child's screen is 1000 columns wide for that file); instructions, descriptions and help say the same, with the argument sizes (16384 bytes for a command, 4096 for the others); D87's question is quoted as the user wrote it; A477 and A483 as the orchestrator recorded them; the mutants M6, M7, M11, M12, M15, M18, M19 are literal edits above; a command called `shell` becomes `shell-2` beside the `\X` shell (help and a case); a sibling directory that only begins like a worktree's is refused (a case); the *aineo-run* paragraph is re-flowed.

## Second fix round (PR #275, the re-measure)

- **N1 (high).** `vim.regex('\v\c(((a{1,1000}){1,1000}){1,1000})')` ended Neovim 0.12.5 with a signal, and `compile()` ran it on every pattern and exclusion before the bounded search, so the pre-allowed `run_output` could kill the user's editor with a 31-character pattern (present since the first version). `compile()` now validates with `pcall(vim.fn.match, '', regex)` (the reviewer's measured edit); no other path compiles the agent's text through `vim.regex`. Regression cases run the pattern, and the exclusion, in a child Neovim and assert it answered and is still running. The exclusion error case now uses `(`, since `[` is taken as itself by `match()` and `search()`.
- **Error wording.** A raised search error is a timeout only when it comes at the end of its allowed time (within 100 ms): measured, the engine reports a search whose time ran out as E363, at 2000 ms. Any other error, memory included, is answered as the editor words it (`pattern: E363: …`). Case: `vim.fn.search` replaced in the child by a function raising E363 at once.
- **N2.** The help says a pattern may span rows with `\n` and that `\%23l` counts the output's rows, from 1. The scratch buffer is created, searched and wiped with `eventignore` set to `all`, restored after (also on an error): a case counts `BufNew`, `BufAdd`, `BufEnter`, `BufLeave`, `BufWipeout`, `BufDelete` and `WinEnter` during a read (none) and reads `eventignore` after (empty).
- **F8 residual (A499).** `command` also refuses DEL and the C1 controls, U+0080 to U+009F (the bytes `\194\128` to `\194\159`); accented text and the no-break space are accepted.
