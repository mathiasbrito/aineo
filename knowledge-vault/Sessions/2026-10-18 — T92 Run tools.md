## Design

- **Three layers for "only when the user asks".** The instructions aineo appends to Claude Code's system prompt (`mcp.run_instructions()`) and the descriptions of `run` and `run_stop` say so; `run` and `run_stop` are not in `--allowedTools`, so Claude Code asks the user for each call and shows the command (the hard gate: instructions cannot guarantee intent); a call no tab runs is not taken. Only `run_output`, which changes nothing, joins `report` and `announce_work` in `mcp.allowed_mcp_tools()` (D87 amends D11's list).
- **The relay side, `lua/aineo/mcp/`.** `run_tools.lua` holds the three tool descriptions and `validate(tool, arguments)`, a table of fields by tool and kinds (`command`, `label`, `text`, `flag`, `count`): a JSON null in an optional field counts as not given, a NUL or a control character (in a name or directory) and an unknown field are refused, the reason naming the field. `protocol.lua` dispatches a valid call to `deliverers.run_call`; `run_calls.lua` offers it to the editor that started Claude Code (`editor.offer_report()` now returns what the editor answered and takes a `subject`, so that a refusal or an unconfirmed call says “call” where a report says “report”), and turns the answer into words: `not taken: …` for a call no tab took, the editor's words otherwise. `mcp.on_run_called()` / `receive_run_call()` are the editor's end, bound once by the composition root, as for an announcement.
- **The editor side, `lua/aineo/entry/`.** `editors.lua` routes a call by its start token (`routing.tab_for_work()`, the tab whose Claude Code holds it) and hands the tab, the project folder and a teller to `run_tools.call()`. `run_tools.lua` is the three handlers, with the dependencies as parameters: `run` resolves `directory` (relative to the folder; real path; accepted only when it is the folder or a worktree from `git worktree list`, which is asked for, with `vim.wait`, only when a directory other than the folder is given), makes the name unused (`sleep`, `sleep-2`), starts through `tab.start_in_run_stack()` and tells the user once; `run_output` and `run_stop` find the process by name (none: the names there are; two: refused, not guessed). `run_pane.start_in_stack()` starts without showing the pane (A476), refreshes a stack that is shown in the current tab page, and makes the quit guard.
- **The run home, `lua/aineo/run/`.** `settings.name`, `entries()` (copies of buffer, name, status), and `read_output(buffer, query)` over `output.lua`'s pure `select(lines, query)`: the terminal's rows without the empty padding; the lines after `after_line` matching `pattern` (a Vim regex, `\v` and `\c` or `\C` put in front) and not `exclude`; the last `last` of them (40 by default, no maximum); `context` lines around each, once where they overlap, clamped to the output and to `after_line`; the number left out; the state. A regex that does not parse is answered with the editor's error naming the field. The answer's text (`entry/run_tools.lua`) is a header with the state and the total lines, which is the `after_line` to follow from, then `12: text` for a match and `13- text` for context, `--` between gaps.
- **Measured here (Neovim 0.12.5).** `vim.regex` with `\v\c` prefixed keeps `^`, `$`, counts, alternation and `(x)@=` working, and a regex that does not parse raises `couldn't parse regex: Vim:E54: …`. A terminal buffer with `'scrollback'` 100 and 300 lines printed held 122 rows, the first `row 180`: rows shift once the output outgrows it. Vim's regex engine has no time limit; four patterns of the shape `(a*)*`, `(a|aa)+`, `(a+)+\1` on 28 characters each took well under a millisecond, but no bound exists.

## Open threads

- `run_output` is pre-allowed and reads every process of the tab's stack, the interactive shell of `\X` included: its screen may hold what the user typed. The brief names the tool by process name only; restricting it is a decision for the user.
- A pattern's cost is unbounded (Vim's engine has no time limit); the pattern comes from the agent without asking.
- `directory` accepts the folder and the worktrees alone, as the brief says: a subfolder is refused, though the command itself can `cd` anywhere the user approves.
- In a tab page other than the current one, a shown run pane lists the new process the next time it is shown.
