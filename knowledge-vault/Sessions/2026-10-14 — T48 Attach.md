## What was done

A start that would resume attaches to the kept session when the list shows it running in Claude Code's background service, and `\S` joins a session running elsewhere instead of refusing it.

- `lua/aineo/claude/init.lua`
  - `launch_once_listed()` asks `agents.running_in_background()` for the kept session; when it answers, `attach_to()` turns the waiting start into an attach (`claude.cmd attach <short id>`, `attached` set, no `--settings` warning, `(attached)` marked) and the launch tells `ATTACHED_NOTE` (51 characters, `INFO`) instead of the interactive warning. There is no question: the user's decision replaced "Ask at start".
  - `stop_running_session()` is the stop the quit and the join share: Ctrl+Z through `stop.detach()` for an attached start, `stop.stop_by_keys()` otherwise.
  - `found_no_conversation()` does not apply to an attached start.
  - `can_join_session()` and `join_session()` (new, public): stop the running Claude Code, launch the picked session in its place (attach, or `--resume` with the warning for a session open in another interactive Claude Code), keep its id for the folder, tell the switch.
- `lua/aineo/claude/agents.lua`: `way_to_join()` (`'attach'` for a background session with a pid or status and a short id, `'resume'` for an interactive one with a pid) and `running_in_background()`.
- `lua/aineo/claude/arguments.lua`: `attach_command()`.
- `lua/aineo/claude/stop.lua`: `detach()` (Ctrl+Z, a wait of `DETACH_WAIT_MS`, then the hang-up `stop_by_keys()` ends with, now `hang_up()`).
- `lua/aineo/claude/session_name.lua`: `mark_attached()`; the status line reads `<name> (attached) — <folder>`; the mark goes when Claude Code exits.
- `plugin/aineo.lua` (widened by the orchestrator's message of 2026-10-14): `claude_settings()` (the start's settings, extracted), `at_empty_prompt()` (the prompt check, extracted from `write_command_at_empty_prompt()`), `join_running_session()`, `take_listed_session()`; `refuses_by_standing()` no longer refuses a session `can_join_session()` accepts.
- `tests/helpers/fake_claude.lua`: given `attach`, it records its arguments, draws the ready screen and exits 0 on Ctrl+Z (`{ ended = 'detach', code = 0 }`); the mode `ignores-detach` does not detach; `AINEO_FAKE_CLAUDE_ATTACH_SAYS` makes the attach print a line and exit 1.
- `doc/aineo.txt`: *aineo-claude-session*, *Stopping Claude Code on quit*, `:Aineo-sessions`, and a limit under *The new session key*.

## Decisions

- **The kept id follows the window by construction.** The attach target is chosen by the kept id, so the attached session already is the kept one. Nothing is written for an attach at a start; a case pins that the file still holds the id and `session_id()` is it. A join writes the picked id (`keep_session_id()`), which is the one place the window changes the kept id.
- **The wait before the hang-up is 4 s, not measured (A227, the orchestrator's assumption).** The user's M16 report gives no time for step 4. 4 s equals the stop's existing longest wait (the third Ctrl-C's 4000 ms) and exceeds the longest exit measured after the second press of a double Ctrl-C (2.5 s); how soon Ctrl+Z ends the attach was not timed. The docstring of `DETACH_WAIT_MS` and the help say the same.
- **A session open in another interactive Claude Code is resumed, not attached (spec conflict; A225 rules it so).** `claude agents --json` gives `id` to background sessions only (`evidence/w12-docs.txt`, D5), so `claude attach` has nothing to take. The orchestrator's message asks to "attach too" with the A166 warning; the pick resumes it in the window with that warning, as a start does. A background session with no short id is still refused with the old words. Reported, not chosen by the brief.
- **No aineo write of a slash command reaches an attached session (A226, fix round).** In an attached window `\N` and `\S`'s switch to a session that does not run go through one replace path (`aineo.claude`'s `is_attached()` and `replace_session()`: prepare, the Ctrl+Z stop, launch, keep the new id): `\N` starts a new session there, `\S` resumes the picked one there. This replaced the first version, in which `\N` wrote `/clear` into the background session. The help's limit now concerns a terminal Claude Code attaches by itself (A231).
- **The settings the resume command was prepared with are discarded at an attach.** `prepare_start()` builds the `--resume` command first; `attach_to()` replaces it. Building it lazily would move `arguments.claude_command()` and its settings file out of the preparation every start shares; rejected.
- **The join prepares before it stops.** An unexecutable `claude.cmd` or a malformed setting raises before the running Claude Code is touched.
