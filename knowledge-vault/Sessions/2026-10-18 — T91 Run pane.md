## Design

- **The home, `lua/aineo/run/`.** Requires no aineo home. It is *given* the folder, the environment and the words of `'shell'` (`settings.cwd`, `.env`, `.shell`) by the composition root, which reads them from `places` and from two new exports of `aineo.shell` (`child_environment()`, `shell_command()`), so the shell's resolution is reused and not copied. `start_command()` runs `{shell…, shellcmdflag…, command}`, `start_shell()` the shell's words; both return a terminal buffer shown in no window. Each process keeps a title in `b:aineo_run_title`, which the winbar `%{get(b:, 'aineo_run_title', '')}` draws (one `%{}` item, so a `%` in a command is drawn as typed). `buffers()`, `running()`, `discard_ended()`, `stop()`, `stop_all()`, `watch_leaving()`; `new()` gives each tab its own copy, with a `let_go()`.
- **Stopping a process with its children.** A terminal's process leads a process group of its own (measured with `ps -o pgid` after `jobstart(term = true)`), so a signal to `-pid` reaches what it started. `:bdelete!` only hangs the pty up: a child that ignores the hangup (`nohup sleep`) outlived it, which the first case of `a process the user deletes` saw. The unload handler therefore signals the group (termination, then a kill after 1.5 s if it still has a member, looking every 20 ms from timers); `stop_all()` does the same synchronously, for the quit and for a tab's close. After the fix round (below) the stop also reaches what a shell under job control moved to groups of its own, and what a process leaves in its group after it ended. A group seen empty is never signalled again (its id may belong to another process by now). Neovim does not stop the tree at exit: it unloads every terminal before `VimLeavePre` and only hangs the pty up, so a process that ignores the hangup outlives the editor unless aineo's stop at `VimLeavePre` sends the kill.
- **The layout, `lua/aineo/layout/`.** `PANE_BUFFERS.run = { report = 'run' }`: the Report's window shows `arrangement.run.buffers[1]`; `sync_run_windows()` opens a window `below` the one before it for each next buffer, reuses the window a buffer already has, closes a window left without a buffer, draws `arrangement.run.winbar` with `vim.wo[window][0]` (`:setlocal`, so another buffer in the window draws the user's own) and equalizes the heights (`equalize_run_windows()`, also run by `apply_proportions()`, so a resize or a closed window shares the rows again). Leaving the pane closes the lower windows and hides their terminals. A pane that takes the whole column is told by the pane table (`takes_whole_column()`), so the terminal pane's Input handling serves both. `show_pane('run')` reads the arrangement every time, shown already or not, since processes come and go; `take_arrangement()` makes the agent pane of a run pane that finds no terminal. A window the screen has no room for (E36) leaves its terminal hidden and says so once. New: `shown_pane()`.
- **The composition root.** `entry/run_pane.lua` is what one tab does with its pane (the prompt, the start, the cursor, following the processes that leave, the windows the user closes); `entry/quitting.lua` is the question and the stops. `entry/tab.lua` hands the layout `run = { buffers, winbar }` in each arrangement and wires the actions; `closing.lua` stops the first tab's processes when its tab page closes (the other tabs' homes `let_go()`); `actions.lua` asks at `\Q`. Nothing about processes is in `layout/` beyond buffers and a winbar string.
- **Keys.** `pane run` → `x`, `run shell` → `X`; a new subcommand `run` taking `shell`; completion, usage, `<Plug>` mappings, prefix keys, twins and the health check's key list follow from the tables.
- **A472, the window the user closes.** `WinClosed` while the run pane is shown: an ended process's buffer is wiped (so it leaves the stack), a running one only loses its window and returns at the next `\x`. The layout notes the other pane before it closes the lower windows of a switch, so a switch is no closing by the user.
- **A474.** Nothing restarts: the home holds nothing the folder's list of tabs keeps.

## What `QuitPre` and `ExitPre` allow (Neovim 0.12.5, measured headless)

- Both fire on `:qa` and `:q` in the last window (`ExitPre` only when the editor would exit); `:tabclose` fired neither (measured on the last tab page, which it refuses with E784).
- Neither tells `:qa` from `:qa!`: `v:cmdbang` is 0 and `v:event` is empty in both. aineo notes the command line entered (`CmdlineLeave`, `:` only, not abandoned) and drops it in the next scheduled callback; the quit commands with a bang in it are forced for this very quit. A quit run by `vim.cmd`, `ZZ`, `ZQ` or a mapping's `<Cmd>` has no command line entered and asks, and a `:q!` typed earlier does not count (the first version read `histget(':', -1)` and stopped processes silently after a stale `:q!`; A484 revised).
- A handler cannot refuse the quit by raising an error, by opening a split or a float, by `:enew` or by moving the cursor: the quit goes on. Closing the current window (with another left) and opening a tab page both make Neovim give the quit up, in `QuitPre` and in `ExitPre`. Closing a window would destroy the layout; a tab page is closed again by a scheduled callback once the command is done, with the cursor sent back. That is what Cancel does.
- `:qa` with a running terminal quits at once (no E947 in the headless child), and `VimLeavePre` runs after it.
- `v:exiting` is 0 (not nil) at the `BufUnload` of every buffer in `:qa`, `:qa!` and `:cquit`, and `BufUnload` of the terminals runs before `VimLeavePre`. Neovim only hangs the pty up, at a quit as at `:bdelete!` (a `sleep` under `sh -c` was alive with ppid 1 after `:qa!` in a plain Neovim). The timers of the editor keep running during its exit, which is why an unload handler that polls can still kill at `:qa`, and why only the `:cquit` case tells the unload handler's early return (F1) from its absence.
- A `VimLeavePre` handler that raises, registered before another, skips the other: measured with `:qa`, `:qa!`, `:x`, `:wq` and `:cquit`, for a Lua callback that raises and for a Vimscript `throw`. The review's probe saw the next handler run; the claim of the help is kept, with this scope.
- A quit that never reaches `ExitPre` (`:cquit`, a signal) cannot be asked about: `VimLeavePre` stops the processes and `vim.notify`s once that it is doing so, unless `ExitPre` ran in the same tick.

## Limits

- The bang is read from the command line entered for this quit (`CmdlineLeave`): a forced quit from Lua, a mapping's `<Cmd>`, `ZQ` or after an older `:q!` asks.
- Cancel opens a tab page and closes it again in a scheduled callback; `TabNew`, `TabEnter` and `TabClosed` autocommands of other plugins run for it.
- A quit refused later (unsaved changes, E37) has been asked about already; the next `:qa` asks again.
- A process that leaves its process group (`setsid`) and is no descendant of the shell is out of reach of the stop; so is a job an interactive shell started under job control and that ignores the hangup, when the shell's terminal is `:bdelete!`d (A485).
- An interactive shell that exits with status 0 is wiped by Neovim's own handler and leaves the stack with no `exited 0` window.
- The modularity skill's tables (§1) have no row for `aineo.run`: it requires no aineo home, and `entry/run_pane.lua`, `entry/quitting.lua` require `aineo.entry.*` and homes through entry points only. The row is an `ai/` change (reported to the orchestrator).
