## What was done

- **The folder's list is kept** (`plugin/aineo.lua`, `write_folder_tabs()`, `keep_folder_tabs()`): the session each aineo tab's Claude Code follows, in the order of the tab pages, and the place of the current tab, or of the aineo tab used last when the current tab page is none of aineo's. It is written when a tab opens (`hold_tab()`), when tab pages close (`close_tabs_of_closed_pages()`, so a tab closed by `\Q` or by Neovim's commands leaves it, U1), when a tab's session changes (`follow_own_session()`) or a dead session is replaced (`hand_over_dead_session()`), and at `VimLeavePre`, from a handler made when the first tab is made so that it runs before the handler that stops the Claude Codes. `:qa` closes no tab page through `TabClosed`, so it keeps every tab. The write is `aineo.tabs`' `keep_tabs()`, T65's file; the logic that builds the list is `aineo.tabs`' `list_of_tabs()` (a tab with no session is left out, a session two tabs show is listed once at the lower place, the place of the current one).
- **The first open reopens it** (`reopen_folder_tabs()`, `ACTIONS.open`): the first run of `:Aineo open`, whatever started it, when no aineo tab exists and `aineo.tabs`' `tabs_to_reopen()` finds a list that holds the session kept for the folder. Each tab opens through `open_new_tab()` (T67's path), the first in the current tab page, each next after the one before it, with `aineo.entry.Tab`'s `open_on_session()` starting Claude Code on the session through `aineo.claude`'s new setting `resume_session`. Every start lists the folder's sessions as a resuming start does (attach where it runs in the background, resume with the warning, replace with a hand-over where Claude Code has no conversation). The tab at the list's place among the tabs reopened ends current; the list is written once, at the end. A first run that finds no such list opens as before; a session restored by a session plugin consumes the reopening (`open_unless_session_restored()`), so a later `\o` reopens nothing either.
- **`aineo.claude`**: `Settings.resume_session`, a session id validated for its form (it becomes an argument to `--resume`), is the choice of `kept_or_new_session()` when set and keeps nothing for the folder; `kept_session()` reads the kept id for the composition root.
- **The user's decision of 2026-10-15: a tab's title is `<number>: <session name>`**, in aineo's tab line and in `tab_title()`. Asked "What should change?" about `<n> <name>`, the user answered, verbatim: "<number>: <session name>". The orchestrator's A321 readings stand (the name is the one aineo keeps, the 24-cell cut counts the name alone, a tab page that is not aineo's shows `<number>: <buffer tail>`); the plan's knowledge pass gives the decision its D-number. The tab line's width math counted the title as a string and needed no change.
- **Help:** *aineo-tabs* (what the folder keeps and what reopening does, that a closed tab does not reopen), *aineo-claude-session* (how the list and the kept id relate), LIMITS › *Several tabs* (two Neovims write one list and the last wins; N tabs run N lists at a reopening; the list after the last aineo tab page closes), the title paragraph.

## Decisions and spec conflicts

- **No spec conflict** with the brief and the plan. The amendment at dispatch records the readings; they stand.
- **The boundary was widened**, as the amendment declares, to `lua/aineo/claude/init.lua`'s `kept_session()` (the composition root may not reach `session_ids.lua`), to `lua/aineo/init.lua`'s docstring of `tab_title()`, to the pins that read a title (`tests/test_tabs.lua`, `tests/test_entry_tabs.lua`) and to `tests/helpers/entry_tabs.lua` (additions only).
- **Writes while tabs reopen are held** (`tabs_reopening`): the list being restored is read once into memory, and a list written meanwhile would replace it with a part of itself. One write at the end.
- **A tab that cannot start** raises its error and leaves the tabs opened before it; the rest are not tried (they would fail the same way).
- **The list after the last aineo tab page closes** (`:tabclose` while other tab pages remain): no write, since `keep_tabs()` refuses an empty list; the list stays as it was before that tab closed, and the next start reopens that one tab. In the help's limits.
- **Not writing the kept id** from a reopened tab: the kept id stays what the last switch or new session in any tab made it, so the session the next start without a list lands in is unchanged (D23, D38).
- **A redraw per reopened tab** was tried to size the background terminals and removed: it changed nothing in the fake's screens (measured), so it is not claimed.

## Findings the reviewers should read

- **A Claude Code started in a tab page that is not the current one draws, in the fake, a screen its readiness check cannot read.** In a child Neovim the second tab's terminal showed the startup screen wrapped at about 57 columns (the status line broke onto the next row, the prompt and its rule ran together) and the input box was never found, so `on_session_ready` never fired for a reopened tab that was not current: no entry among the running editors, no `follow_own_session()`. Entering the tab did not change it; the fake draws once and does not redraw on a resize. With the real Claude Code, which redraws on a resize, the effect is unmeasured; it is the user's check M3. The suites therefore tell a reopened tab's session by its process (`tests/helpers/entry_tabs.lua`' `start_arguments_in_tab()`), never by its entry, and the cases that must see the list change without readiness run the fake in its `exit` mode.
- **Entry suites that share a state home**: the list is one file per folder, so a case that leaves several tabs and a kept session in the list would have the next case of the same file reopen them, as the kept id was already shared. The existing entry suites ran green unchanged (see *Suites*).
