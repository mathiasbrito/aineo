## What was done, and why

`presets/lua.lua` is one file of data like the other languages': three presets and the default. `presets/init.lua` requires it after C++, so `presets.ids()` (the MCP tool's instruction sentence, `preset_ids()`) names the three ids with no further change.

busted and plenary are two-way mirrors: `lua/{path}/{name}.lua` (and, for busted, `src/…`) give `spec/…_spec.lua` or `tests/…_spec.lua`, so a test file's source is found by the reverse template. Both are marked `convention`, since the `_spec` pattern is documented and the folder is not.

mini.test's flat name needs the plugin's folder dropped and the others joined with `_`. The template engine joins with `{path|_}` but a joined `{path}` that stands for no folder leaves a name with two underscores, and a modified placeholder in a source template stands for one segment. The preset therefore has five rules in order: an `init.lua` one folder below the plugin's, an `init.lua` deeper, a file one folder below, a file deeper, a file directly in the plugin's folder. Each deeper rule matches the shallower sources too (with an empty `{path}`), and the shallower rule is listed first, so a new test file is named by the shallowest.

With the `init.lua` rules first, the first rule's test template matches every flat test file and binds no `{name}`, so the way back by stem finds nothing. A691 ruled that `aineo.test_layout.modules` read Lua instead: `lua_imports()` reads `require('a.b.c')`, `require "a.b.c"` and `require [[a.b.c]]` with a literal name as a path the source ends with (`a/b/c.lua`, `a/b/c/init.lua`), and `patterns()` gives a source's module name (the path below `lua/` or `src/`, a folder's `init.lua` by the folder) for the text search of the test files that require it.

## Decisions (the implementer's, within A690 and A691)

1. The five-rule shape above; the engine and the marker reader are unchanged.
2. `create = true` was tried to let the general rules come first (so a test file could be mapped back to its source) and dropped: finding takes the first rule marked `create` across all rules in force, so a preset's `create` beats the agent's own rules. A red seen: with it, the busted and plenary creation cases returned `tests/test_fee.lua` for a busted rule.
3. The `init.lua` rules therefore come first, and the source of a mini.test test file is found by the modules it requires (A691), not by stem. The packet first reported this as a spec conflict and pinned the missing way back with a case; A691 replaced the pin by the reading of Lua `require`.
4. The marker reader's `holds` is a plain-text search of a file a glob names, so: busted `.busted` and a root `*.rockspec` holding `busted`; plenary a `Makefile` or any `minimal_init.lua` holding `PlenaryBustedDirectory`; mini.test a `tests/**/test_*.lua` file, or a `minimal_init.lua` or `Makefile` holding `mini.test`.
5. The fixture tree holds no `test_*.lua` file, which `make test` collects as a test file; cases that need an existing mini.test file write it into the copy of the tree. A mini.test case that names a rule of its own also writes a pairing file, since an agent's rule that pairs nothing while busted pairs some is kept after it.
6. The agent's instruction sentence needs no edit: it is built from `presets.ids()`.
7. The Lua reader is a small scanner, not a pattern: it skips line and long comments, quoted and long strings (of any level, closed at their own level), and takes `require` only as a whole word not preceded by `.` or `:`, with a literal alone between the parentheses, if any, and a name of letters, digits, `_`, `-` and dots. A file in the test's own top folder (`tests/`) is never the source (`outside` on the imported source): a helper the test requires would otherwise outrank the module under test, being the shorter path.
8. A guard against `..` in a required name was written and removed: a name with `..` gives a path no source ends with, so the guard was measured equivalent (its mutant survived on the two test files that exercise it).
