## What was done, and why

`presets/lua.lua` is one file of data like the other languages': three presets and the default. `presets/init.lua` requires it after C++, so `presets.ids()` (the MCP tool's instruction sentence, `preset_ids()`) names the three ids with no further change.

busted and plenary are two-way mirrors: `lua/{path}/{name}.lua` (and, for busted, `src/…`) give `spec/…_spec.lua` or `tests/…_spec.lua`, so a test file's source is found by the reverse template. Both are marked `convention`, since the `_spec` pattern is documented and the folder is not.

mini.test's flat name needs the plugin's folder dropped and the others joined with `_`. The template engine joins with `{path|_}` but a joined `{path}` that stands for no folder leaves a name with two underscores, and a modified placeholder in a source template stands for one segment. The preset therefore has five rules in order: an `init.lua` one folder below the plugin's, an `init.lua` deeper, a file one folder below, a file deeper, a file directly in the plugin's folder. Each deeper rule matches the shallower sources too (with an empty `{path}`), and the shallower rule is listed first, so a new test file is named by the shallowest.

With the `init.lua` rules first, the first rule's test template matches every flat test file and binds no `{name}`, so the way back by stem finds nothing. A691 ruled that `aineo.test_layout.modules` read Lua instead: `lua_imports()` reads `require('a.b.c')`, `require "a.b.c"` and `require [[a.b.c]]` with a literal name as a path the source ends with (`a/b/c.lua`, `a/b/c/init.lua`), and `patterns()` gives a source's module name (the path below `lua/` or `src/`, a folder's `init.lua` by the folder) for the text search of the test files that require it.

The review of the pull request (A692) found that the pick among several requires was the shortest path, not the test's subject (five of 58 pairings in this repository were wrong), that the exclusion of the tests folder hid sources in a unit below the root and a co-located spec, that a crafted 1 MiB test stalled `source_for` for 36 s, and a few gaps in the reader. `way_back` now puts first the imported sources some rule gives this test file for; the exclusion lives in `is_imported_source` (the way back only) and is relative to the unit (`imported()` takes it); `imported()` gives the first 64 distinct imports for every language, a Lua `require` being one import (`lua_module`); the reader reads `pcall(require, 'a.b')` and CR line ends, and a source's search string strips one of `lua/` and `src/` only.

## Decisions (the implementer's, within A690, A691 and A692)

1. The five-rule shape above; the engine and the marker reader are unchanged.
2. `create = true` was tried to let the general rules come first (so a test file could be mapped back to its source) and dropped: finding takes the first rule marked `create` across all rules in force, so a preset's `create` beats the agent's own rules. A red seen: with it, the busted and plenary creation cases returned `tests/test_fee.lua` for a busted rule.
3. The `init.lua` rules therefore come first, and the source of a mini.test test file is found by the modules it requires (A691), not by stem. The packet first reported this as a spec conflict and pinned the missing way back with a case; A691 replaced the pin by the reading of Lua `require`.
4. The marker reader's `holds` is a plain-text search of a file a glob names, so: busted `.busted` and a root `*.rockspec` holding `busted`; plenary a `Makefile` or any `minimal_init.lua` holding `PlenaryBustedDirectory`; mini.test a `tests/**/test_*.lua` file, or a `minimal_init.lua` or `Makefile` holding `mini.test`.
5. The fixture tree holds no `test_*.lua` file, which `make test` collects as a test file; cases that need an existing mini.test file write it into the copy of the tree. A mini.test case that names a rule of its own also writes a pairing file, since an agent's rule that pairs nothing while busted pairs some is kept after it.
6. The agent's instruction sentence needs no edit: it is built from `presets.ids()`.
7. The Lua reader is a small scanner, not a pattern: it skips line and long comments, quoted and long strings (of any level, closed at their own level), and takes `require` (or `pcall(require, …)`) only as a whole word not preceded by `.` or `:`, with a literal alone between the parentheses, if any, and a name of letters, digits, `_`, `-` and dots. A file in the top folder of the unit the test sits in (`tests/`) is not the source the way back gives (`outside` on the imported source, checked by `is_imported_source`): a helper the test requires would otherwise outrank the module under test, being the shorter path. `test_for` does not use the exclusion, so a spec beside its source is found.
8. A guard against `..` in a required name was written and removed: a name with `..` gives a path no source ends with, so the guard was measured equivalent (its mutant survived on the two test files that exercise it).
9. The pick among the imported sources (A692 (1)): the reviewer's measured fix, adopted red-first. `way_back` keeps its order — the stem, then the imports — and within the imports puts first those for which a rule in force gives back this test file (`tests_of`), then the others, each group shortest path first. It holds for every language; in this repository it changes exactly the five wrong pairings the review found.
10. The bound (A692 (3)): 64 distinct imports, not 64 entries, so a Lua `require` had to become one entry (`lua_module`, matched as `a/b/c.lua` or `a/b/c/init.lua` in `is_imported`) instead of two `ends_with` entries. Distinct is judged by the path, folder or module an import names. A probe of the review's shape (a regular 1 MiB file of requires, 2000 tracked files) took 78 ms here against 36 s measured in the review. The case asserts by count (what is read), not by time.
11. The `costs each call little` case allows a second per call instead of 100 ms (A692 (6)): it flaked once in four under load, and without the step budget a match runs for minutes, so it still tells. Not mutated: removing the budget would hang the file.
12. Nested mini.test test files (`tests/unit/test_x.lua`) stay a limit (A692 (5)): the five rules' test templates are flat, so no rule names them and the way back gives them no source; the discovery glob still marks them as tests.

## Open threads

- A rockspec marker is a `*.rockspec` at the root only (the glob has no `**`), so a rockspec in a folder does not mark busted.
- Creating a test for a mini.test source that has no folder below the plugin's (`lua/kit/init.lua`) gives `tests/test_init.lua`, as A690 (5) asks.
- The Lua reader reads `require` and `pcall(require, …)` with a literal name, not `dofile` or `loadfile`: a test that loads its subject by `dofile` finds no source by import. It also counts `loader . require('x')` (spaces around the dot) and `x:\nrequire('x')`, which A691's literal forms leave out.
- Nested mini.test test files (`tests/unit/test_x.lua`) have no source: no rule names them (decision 12).
- The search string of a plugin's root module (`lua/aineo/init.lua` searches `aineo`) is broad: `test_for` of it took 1.5 s on a cold cache in this repository in the review, against about 0.3 s for other sources.
