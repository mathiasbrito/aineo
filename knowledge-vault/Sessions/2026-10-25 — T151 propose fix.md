## What was done, and why

1. **Placement** (`aineo.explain.placement`, pure): an edit is placed at the lines it names when it names as many lines as its old lines and they are those lines byte for byte, else at the one other place they stand as a block; the whole fix is refused, with the reason, on a malformed edit (anything but `line`, `last`, `old`, `new`, `why`), line numbers the text lacks, no old lines, a line break (`\n` or `\r`) or NUL in a line, no match, several matches, or overlap. Edits that touch are placed, in line order.
2. **Request and answer**: `request.FIX_SCHEMA`; `arguments()` takes a `schema` option (the explanations' schema stays the default); `fix_prompt()` is the steer or the default text, then a fixed part naming the issue (line, file, text) and the answer's rules, then the numbered buffer. `answer.fix_in()`; `answer.failure_of()` now reads a failed run for both requests.
3. **The flow** (`aineo.explain.fix`): the issue on the line (`marks.issue_at()`: the marked one, else the first); the run shows `proposing a fix…` as the other requests show their work; on its end, the tick check, the failure, an empty edit list (its summary told), a refusal, else the preview. Asking again stops the running request and removes the fix shown. A steered request opens `aineo.explain.steer` under the name `fix`.
4. **The preview** (`aineo.explain.preview`): a range extmark per edit from the start of its first old line to the start of the line after its last; `conceal_lines` hides the old lines; rows are drawn per place, one extmark each; the head row (keys) and each edit's fix explanation (summary, then why) precede its new lines. `\Vd` toggles the diff view. Accept re-checks every edit, then applies bottom-up from positions read before the first change. The edit watch drops on a touching edit (scheduled) or a detach while loaded (a reload), quietly on unload, and redraws after other edits. Keys are buffer-local, told by their `desc`.
5. **Draw** (`aineo.explain.draw`): the band drawing moved out of `marks.lua`, unchanged, so the preview draws its bands without a copy.
6. **Entry, plugin, health, help, README**: as the T151 row lists.

## Decisions (the implementer's, within A627 and A628)

- **One extmark per place, so the fix explanation has no namespace of its own** (A628 asked for one). Measured on Neovim 0.12.5: the virtual lines of several extmarks at one place draw in no promised order (three marks at one place, one namespace, drew 1, 3, 2; `priority` did not order them; across namespaces the order followed neither insertion nor namespace). The head, the fix explanation and the new lines of a place are therefore drawn by one extmark in the preview's namespace; the fix explanation keeps its own look (`kinds.FIX_WHY`: label `why`, `AineoFixWhy*`, `DiagnosticHint`). Reported as a spec conflict.
- **The summary heads every edit's fix explanation**, as A628's "the summary on its first row then the edit's `why`" reads; with several edits it repeats.
- **`'concealcursor'` gains `n` while a fix is shown** (A627 names only `'conceallevel'`): the cursor sits on the issue's line when `\Vf` is pressed, and without it that line, an old line, stayed visible (measured). Both options are restored exactly.
- **Window options with `:setlocal` scope**, so another buffer a window comes to show keeps its own; a window that comes to show the buffer while a fix is shown gets back, when it goes, the options the buffer had where the fix was asked (entering a buffer takes the window options from the buffer, measured, so the options that window had for another buffer are not the ones to restore).
- **A reload drops the fix with a word**: `:edit!` detaches `nvim_buf_attach` (no `on_reload`, measured), so a detach while the buffer is loaded drops it; a detach while unloaded removes it quietly.
- **The drop is scheduled**, so accept's own re-check is what guards an edit made in the same tick (the test of that refusal edits and accepts in one call).
- **Diff view**: the head and explanation sit above the first old line at column 2, after the issue band shown there; the overlay hangs a block of touching edits below the line before it, or above the line after it at the buffer's start; a block spanning the whole buffer shows as the diff view does.
- **`:Aineo explain clear` removes the fix too** (A627 is silent): a preview over a cleared buffer would keep its old lines hidden.
- **The head row is wrapped** as the fix explanation is: with no prefix it names the `<Plug>` mappings, which did not fit an 80-column window.
- **The issue's text goes in the fixed part**, not the editable text, so a remembered steer never names another issue (as A626 did for the file and lines).
