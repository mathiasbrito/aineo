## What was done, and why

1. **One table of keys** (`aineo.keys`, A636 (3)). The keys were in five tables of `plugin/aineo.lua` (`PREFIX_KEYS`, `EXPLAIN_KEYS`, `FIX_KEYS`, `CLEAN_KEYS`, `HAS_NO_TWIN`) and a copy in `lua/aineo/health.lua`. Each key is now one row: its suffix or keys, `<Plug>` name, `:Aineo` command, group, phrase, modes, whether it has a twin in Terminal and Insert mode, and whether it is mapped in the editor or in a buffer. The rows are in the order the keys were mapped in, so the first mapping told to the user and the order of the health report stay; `sheet()` gathers them by group. The context groups (a fix shown, the steering float, jumping, the changes pane, the explorer) are rows too, flagged as buffer keys.
2. **The cover shared** (`aineo.cover`, A636 (2)). The office's float moved to a small home with options (filetype, name, enter, mouse); the office opens its window through it and behaves as before (test_office green on it).
3. **The sheet** (`aineo.cheatsheet`). `compose` is pure: title row, a group per heading in its own accent, keys in that accent, phrase, command dimmed right-aligned or on a line of its own when it does not fit; two columns from 80 cells, the groups split so the columns are as even as they can be, the left taking the more when two splits tie; no line wider than the window. The window follows the right column, writes the sheet again for a new width, closes on `q`, `<Esc>`, toggling, when the cursor leaves it and when the layout has no right side. `AineoCheat*` highlight groups are derived from the scheme's groups and defined again on `ColorScheme`; a group the user defined stays.
4. **The composition root**: `aineo.entry.cheatsheet` (the tab's sheet, let go with the tab) and `cheatsheet_keys` (each key as the user types it: prefix and suffix when mapped to the row's `<Plug>`, else the first key mapped to it, as when the user mapped it themselves, else the `<Plug>` name; buffer keys with the prefix, or the `<Plug>` name when the prefix is `false`; the tab keys as `\1…\9`). `:Aineo cheatsheet` is a subcommand; `\?` has no twin in Terminal and Insert mode (A636 names Normal).
5. **Exclusivity** (A636 (2)): opening the office, its reset or its preview closes the sheet first (`actions.lua`); the office closes itself when the cursor enters a window it covers, which the sheet's window is, so opening the sheet closes the office with no call of its own, and the office's idle countdown cannot show it over the sheet, since the cursor in the sheet is in the right side.
6. Help (`aineo-cheatsheet`, `:Aineo-cheatsheet`, `<Plug>(aineo-cheatsheet)`, `aineo-\?`), README keys row, the plan note's D126 and T153 rows.

## Decisions (the implementer's, within A636)

- **`plugin/aineo.lua` loads `aineo.keys` at `VimEnter` besides the configuration**, so the case that said it loads the configuration alone now names both, and `aineo.keys` loads nothing.
- **The rows keep the mapping order**, not the sheet's, because the health report's and the startup error's order are asserted by cases and a second order would be a second list.
- **A key shown that the user mapped over** (prefix key taken by their own map) shows as the `<Plug>` name, since that is all there is to press; a key the user mapped to the `<Plug>` themselves shows their key.
- **The sheet closes when the cursor leaves it**, as the office does when the cursor enters a window it covers; the cursor stays where the user moved it.

The deep-require check prints no line from outside a home.
3. **The plugin file now loads `aineo.keys` at `VimEnter`** (see the decisions); its docstring and the case say so.
