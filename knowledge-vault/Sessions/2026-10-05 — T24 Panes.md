## What was done

- **`lua/aineo/layout/init.lua`** (C2, C9, C12):
  - The state gains `pane` (`'agent'|'changes'`, for the editor's life) and the Report's `b:changedtick` when the agent pane was last hidden. `state.buffers` keeps the changes pane's two buffers by name, `files` and `commits`.
  - `PANE_BUFFERS` and `own_buffer(role)` say what each window shows as its own under the pane shown. Every read of "a window's own buffer" goes through it: `build()`, `reopen_closed_windows()`, `show_buffers()`, `redirect()` and `redirect_when_file()`. So `\o`, a layout built anew, a reopened window and the file column's redirect all keep the changes pane (D21, PD6 (a), PN3, PN4).
  - `M.show_pane(pane, arrangement)`: switches in place with `nvim_win_set_buf()`, the windows kept by id and size, the cursor left where it is (PD5 (a)); does nothing for the pane shown. It opens the layout first, with `arrangement` (a table or a function called only then), when either right-column window is gone or a buffer of the pane was wiped or unloaded (PD4 (a)). On the agent pane's return the Report and Input wrap, and the Report's cursor goes to its last line only when its `b:changedtick` moved while hidden (PD3 (b)).
  - `M.focus()` of the Report or Input shows the agent pane first (PD1 (a)); `\c` and `\tcn` leave the pane alone.
  - T16's wrap is set only while the agent pane shows (`wrap_agent_pane()`), so the placeholders keep the user's own settings.
  - The arrangement gains an optional `changes = { files, commits }`, validated like the rest. `show_pane('changes')` with no changes buffers ever handed raises, naming `arrangement.changes`, before switching.
- **`plugin/aineo.lua`** (C1):

  - The placeholders are made here, `aineo://changes-files` and `aineo://changes-commits`, by `changes_pane()`, inside `arrangement()`. ## Decisions & reasoning

- **PD1–PD6, the user's**, each built as the amendment records it: PD1 (a), PD2 (a), PD3 (b), PD4 (a), PD5 (a), PD6 (a).
- **The seam:** an optional `changes` field (*The seam for T25*).
- **PD3, measured by `b:changedtick`**, not by line count: the first report into an empty Report replaces its one line (`append_rendering()`), so the count would not move.
- **`:bdelete` handled as `:bwipeout` is.** Measured: a deleted placeholder comes back empty, with an empty `'buftype'`, and modifiable. The layout counts a pane's buffer as there only while it is loaded, and the composition root makes it anew.
- **`switch_pane()` acts only on the right-column windows that exist**, so `\r` with Input's window closed under the changes pane shows the Report alone, as `\r` behaves today. `show_pane()` itself opens the layout first then (the orchestrator's reading of PD4 (a)).

## Readings for the MVP review

- The `<Plug>` names `<Plug>(aineo-pane-agent)` and `<Plug>(aineo-pane-changes)`, and the placeholder names `aineo://changes-files` and `aineo://changes-commits`: the orchestrator's.
- The placeholder's words, the author's: "aineo does not list the session's changed files here yet" and "aineo does not list the session's commits here yet". They claim nothing about the repository.
- `\pa` and `\pc` on the pane shown change nothing and say nothing.
- A user's own `\p`, or `<Leader>p` while `\` is the leader, now waits for `'timeoutlen'` (P1); the help says so.
- `:Aineo pane`'s usage: `aineo: :Aineo pane takes one of agent, changes`.
- `:Aineo`'s general usage now lists `pane` last.
- Completion counts the words after the command's first word, so `:silent Aineo pane ` offers nothing. A modifier before `:Aineo` was judged rare.
- `\pc` from another tab switches the layout's pane in its own tab and leaves the cursor where it is, as `\tcn` acts from any tab.
