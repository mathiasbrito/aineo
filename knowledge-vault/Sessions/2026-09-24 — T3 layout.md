## Context

**Goal.** T3 builds aineo's screen:
- C2 — the three windows, pinned against resizing, restored by `\o`;
- C9 — the file column, and the `BufWinEnter` redirect that fills it.

The entry point (T7) wires T3 to the prefix keys and to startup. Until then, nothing calls the layout.

## What was done

**`lua/aineo/layout/init.lua`**, the home's one file. Its entry point is `require('aineo.layout')`:

- **`open(arrangement)`**
  - **What it is handed:** `arrangement` is `{ claude, report, report_height }` — the Claude terminal buffer, the Report buffer, and the Report's share of the right column.
  - **The first call builds the layout.**
    - Claude's buffer on the left, at half the columns (D4).
    - The Report above Input on the right, taking `report_height` of that column (D13).
    - The cursor in Input.
  - **What happens to the tab.** Its other windows close, and their buffers stay loaded. A file shown in the current window stays, as the file column.
  - **Input.** It is made once, from the unnamed, empty buffer Neovim starts with, or else as a new buffer. It is named `aineo://input`, `nofile`, unlisted, `bufhidden=hide`, with no swap file.
  - **Later calls restore.** While any of the three windows exists, a call:
    - reopens only the windows that were closed, in their places;
    - shows each window its buffer — the handed Claude and Report buffers;
    - puts the proportions back;
    - leaves the cursor where it is.
  - **Its arguments are checked** with `vim.validate`, and the error names the setting.
- **`focus(role, arrangement)`**: moves the cursor to the Claude, Report or Input window. When that window is gone, it reopens the layout first (L12).
- **`input_buffer()`**: returns the Input buffer, for T6.

**Behind the entry point.**

- **Pins.** The three windows carry `'winfixwidth'` and `'winfixheight'`.
- **Re-applied proportions.** They are put back after every `WinClosed` (scheduled, and only while the three windows exist) and every `VimResized`.
- **The redirect.** A `BufWinEnter` on a file (empty `'buftype'`) in one of the three windows schedules a move:
  - the file goes to the file column, created right of Claude's column on first use and reused after;
  - the window gets its buffer back;
  - the cursor lands in the file column, on the position the command gave it.
  - When the move runs, it checks that the layout is still open and that the window still shows the file.
- **The file column** is found structurally: the columns of the layout's tab between Claude's column and the right one, read from `winlayout()`. With it open, the three columns take equal thirds (D6).

## Decisions & reasoning

**The orchestrator's readings, as briefed:**
- L1 — the cursor ends in Input.
- L3 — the tab's other windows close.
- L4 — re-apply on `WinClosed`.
- L6 — re-apply on `VimResized`.
- L11 — non-files are left alone.
- L12 — focus reopens.

**Mine:**

- **R1 — the redirect is scheduled, not synchronous.**
  - Measured in a spike (Nvim 0.11.6, a mini.test child), a synchronous redirect inside `BufWinEnter`:
    - left the cursor in the aineo window;
    - applied `:edit +3`'s and `:cfirst`'s cursor step to the aineo window.
  - A scheduled redirect has no such problem, provided it captures the window when the event fires and carries the cursor over.
  - *Rejected:* `'winfixbuf'` (A5, F3 — it refuses where D7 redirects), and `BufReadPost` (a loaded file shown with `:buffer` never fires it; a mutant measures this).
- **R2 — the file column is structural (`winlayout()`), not one remembered window.**
  - With the column split in two, closing the window a file first opened in left the column on screen.
  - The layout then sized itself as if the column were gone (Claude at 40 of 80 columns), and would have opened a fourth column on the next file.
- **R3 — `open` while any of the three windows exists restores, and leaves the cursor where it is.** No row says where `\o` puts the cursor.
- **R4 — only an *empty* unnamed buffer becomes Input.** Text typed into the unnamed buffer is a file (empty `'buftype'`), and stays in the file column.
- **R5 — Input is unlisted and kept when hidden.** It is made once, per editor.
- **R6 — `focus` takes the arrangement, so it can reopen.** `report_height` has no default in the layout; the composition root (T7) resolves it from `aineo.config`.

**Test design.**

- **Geometry tolerance: one cell.** A vertical separator takes a column and a status line a row, and no window counts either. Before-and-after comparisons (L4, L5) compare exactly.
- **The tests read scheduled results with their next request, without a wait.** A child runs a callback scheduled while serving one request before it serves the next. This is stated in `tests/helpers/layout.lua` and measured: 5 of 5 pristine runs green, and M10–M12 killed 3 of 3 times with the same cases.
- **Claude's terminal content is compared as its job channel, not its lines.** A terminal's lines grow with its window asynchronously; they were measured changing between two reads.
