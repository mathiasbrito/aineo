## Context

**Goal:** T23, C13's git home, for the changes pane (T25), its only caller: a directory's repository, the files changed since a base commit, the commits since it, a file's and a commit's unified diff, and a watch that calls back when the branch moves (D22) or a working-tree file changes (D19) — every git call asynchronous and time-bounded. Nothing is visible to the user yet: no command, key, window, help section or health check.

## What was done

`lua/aineo/git/`, a new home that requires no other aineo home:

- **`init.lua`** — the public surface: `find_repository(directory, done, options)`, `changed_files(repository, base, done, options)`, `commits_since(repository, base, done, options)`, `file_diff(repository, base, change, done, options)`, `commit_diff(repository, commit, done, options)`, `watch_repository(repository, on_change, options)`. Every `done` is `done(failure)` or `done(nil, result)`.
- **`process.lua`** — runs git as a list, `git -C <directory> -c core.quotePath=false -c core.fsmonitor=false …`, with `GIT_OPTIONAL_LOCKS=0`, bounded by `limit_ms` (10 s by default) with a timer that kills the process (SIGKILL) and reports `timed_out`; a git that cannot start is `no_git` in `vim.system`'s words, without Neovim's file and line; `done` is always scheduled on the main loop, never before the call returns. The run returns a cancel function, used by the watch.
- **`repository.lua`** — GH1: one `rev-parse --show-toplevel --absolute-git-dir --path-format=absolute --git-common-dir`, then `rev-parse --verify --quiet HEAD` and `symbolic-ref --quiet HEAD` (exit 1 is an answer: no commit, no branch). Exit 128 at discovery is `not_a_repository`, in git's words. A nil base compares with the empty tree, asked of git (`hash-object -t tree /dev/null`), so a SHA-256 repository gets its own.
- **`changes.lua`** — GH2: `diff --name-status -z -M --end-of-options <base> --` on a private index, then `ls-files --others --exclude-standard -z`; kinds `added`, `modified`, `deleted`, `renamed` (with `old_path`), `type_changed`, `untracked`.
- **`history.lua`** — GH3: `log -z --format='%H %s' --no-show-signature --encoding=UTF-8 --ignore-missing --end-of-options <base>..HEAD --` and `merge-base --is-ancestor` (exit 1 an answer).
- **`diffs.lua`** — GH4, GH5: the unified-diff flags `--no-color --no-ext-diff --no-textconv --src-prefix=a/ --dst-prefix=b/ --unified=3 --find-renames --full-index`; an untracked file through `diff --no-index -- /dev/null <path>` (exit 1 an answer); a rename asked with both paths; `show` with `--pretty=medium --no-abbrev-commit --no-decorate --no-notes --date=default --encoding=UTF-8 --no-show-signature`.
- **`private_index.lua`** — GH8: both diffs run with `GIT_INDEX_FILE` pointing at a copy of the index in Neovim's temporary directory, removed (with any `.lock` beside it) when the diff ends; a missing index is an empty one; an index that cannot be copied is a failure.
- **`watch.lua`** — GH9: a watch on the top level (events in `.git` set aside) and one on the common git directory, recursive where libuv watches recursively (`Darwin`, `Windows_NT`, from `vim.uv.os_uname().sysname`, which a caller may replace as `system_name`); a 200 ms settle after the last event ends a burst; a burst that touched the git directories reads `HEAD` again and compares commit and branch. Reads are serialized; `stop()` cancels one in flight, releases every handle, and does nothing the second time.

Tests: `tests/test_git_repository.lua`, `test_git_process.lua`, `test_git_changes.lua`, `test_git_commits.lua`, `test_git_diffs.lua`, `test_git_configuration.lua`, `test_git_lock.lua`, `test_git_watch.lua`, and `tests/helpers/git_repo.lua`. Every case runs the home in a child Neovim whose environment carries `tests/helpers/git.lua`'s `HERMETIC_ENVIRONMENT` and `GIT_CEILING_DIRECTORIES=<checkout>/.tests/fixtures`; every fixture is `.tests/fixtures/git-<name>`.

## Decisions

- **GH8's mechanism: a private copy of the index**, over `-c diff.autoRefreshIndex=false`, which lists every stat-dirty file as modified (the brief review's finding 1). Pinned twice: `.git/index`'s inode, size and mtime unchanged after a read over three stat-dirty files; and a watch on `.git` that starts a `git commit` the moment `index.lock` appears, then a marker file whose event ends the watch — no lock is ever seen. Against the repository's own index both cases fail (mutants C4, D17).
- **GH7 by flags, never by switching the user's configuration off** (the brief). Two departures from the brief's measured set, each measured: `--src-prefix=a/ --dst-prefix=b/` for `--default-prefix` (git 2.41), since the older pair neutralises `diff.noprefix` and `diff.mnemonicPrefix` the same way; and no `--no-relative`, since every command runs at the top level, where `diff.relative=true` changes nothing (the hostile cases run from a subdirectory and pass).
- **`--end-of-options` before the revisions of `diff`, `log` and `show`**: a base or commit that reads as an option — `--output=<file>` — is refused and writes nothing. Not in the brief; found while writing GH5, since `git show --output=<file>` writes a file. `merge-base` has no such option and fails on one either way, so it has none (mutant H8).
- **The watch compares `HEAD`, it does not trust an event** (the brief review's finding 2): a watch on the whole common directory rather than on `logs/HEAD`, so a reflog replaced by `gc` or `reflog expire`, a repository with no commit yet and an `update-ref` from another worktree are all seen.
- **Failure shape**: `{ reason, message, code? }`, `reason` one of `not_a_repository`, `no_git`, `timed_out`, `failed`.

## Readings for the MVP review

The orchestrator's, from the brief: the watch fires on working-tree changes by any process, the user's included, and T25 marks the user's saves; paths are relative to the top level; a base that is no longer an ancestor of `HEAD` is reported, not repaired; the home keeps no state but its watches, and the base is T25's; a new file is untracked and not excluded by `.gitignore`, `.git/info/exclude` or the user's `core.excludesFile`; a file counts as renamed only once the rename is staged or committed.

Mine, taken in this packet:

- **"Not a repository" is exit 128 of the discovery command**, not a match on git's words, which git translates: a missing directory, a bare repository and a repository git refuses for its ownership are reported the same way, each in git's own words, which say which.
- **A copy is listed as added.** GH2 asks for a `copied` kind when the user's `diff.renames=copies` asks for it; GH7 asks for `-M`, which turns copy detection off (measured). See *Spec conflicts*.
- **The minimum git** the flags imply is **2.31**, for `rev-parse --path-format=absolute` (git's 2.31.0 release notes, read). `--end-of-options` is 2.24 (release notes, read). The others I did not read in release notes: `--absolute-git-dir`, `--ignore-missing`, `--no-show-signature`, `GIT_OPTIONAL_LOCKS` (2.15) and the boolean `core.fsmonitor` are older than 2.31 as I recall them, unverified.
- **Linux**: the watch says `watches_subdirectories = false` and watches the top directory and the common git directory alone; a commit there rewrites the index, which that watch sees, but a branch moved by `update-ref` from another worktree, or a `reset --soft`, is not seen there (not measured: no Linux host).

## Open threads

- **The copied kind** (see *Spec conflicts* in the report and the pull request): GH2 against GH7. T25 or the user decides whether a copy the user's `diff.renames=copies` asks for should show as copied.
- **An editor started with `GIT_DIR`, `GIT_WORK_TREE` or `GIT_INDEX_FILE` in its environment** (a Neovim opened by a git hook, for instance) hands them to every git the home runs, which then reads that repository, whatever `-C` says. Not in the brief; not handled.
- **`core.splitIndex=true`**: git writing the private copy may write a `sharedindex.*` file into the repository's git directory. Not measured.
- **Linux**: not measured. The watch says it cannot see subdirectories; its git-directory watch sees the index and `HEAD` rewritten there, not a `reset --soft` or a move from another worktree.
- **A directory whose path holds a newline**: `rev-parse` prints the top and the git directories one per line, so such a top level is misread.
- **The fs_event callback's error argument is not read**: I found no way to make libuv report one on macOS for a case, and wrote no code for it.
- The timer's `is_closing()` check before the kill guards a race (the process ended in the same loop turn as the limit) that no case reaches.
