## Context

## What was done

`lua/aineo/git/`, a new home that requires no other aineo home:

- **`init.lua`** — the public surface: `find_repository(directory, done, options)`, `changed_files(repository, base, done, options)`, `commits_since(repository, base, done, options)`, `file_diff(repository, base, change, done, options)`, `commit_diff(repository, commit, done, options)`, `watch_repository(repository, on_change, options)`. Every `done` is `done(failure)` or `done(nil, result)`.
- **`process.lua`** — runs git as a list, `git -C <directory> -c core.quotePath=false -c core.fsmonitor=false -c core.bigFileThreshold=512m -c diff.suppressBlankEmpty=false …`, with `GIT_OPTIONAL_LOCKS=0` and `GIT_LITERAL_PATHSPECS=1`, and without the editor's repository-local `GIT_*` variables (`clear_env`, the editor's environment less that list); its output kept byte for byte (`text = false`). git leads a process group of its own (`detach = true`); at `limit_ms` (10 s by default) a timer kills the group with SIGKILL and reports `timed_out`. A git ended by a signal is `failed`, never an answer. A git that cannot start is `no_git` in `vim.system`'s words, without Neovim's file and line; `done` is always scheduled on the main loop, never before the call returns. The run returns a cancel function, used by the watch.
- **`repository.lua`** — GH1: one `rev-parse --show-toplevel --absolute-git-dir --path-format=absolute --git-common-dir`, whose three lines must be exactly three (a path holding a newline is `failed`), then `rev-parse --verify --quiet HEAD` and `symbolic-ref --quiet HEAD` (exit 1 is an answer: no commit, no branch). Exit 128 at discovery is `not_a_repository`, in git's words. A nil base compares with the empty tree, asked of git (`hash-object -t tree /dev/null`), so a SHA-256 repository gets its own.
- **`changes.lua`** — GH2: `diff --name-status -z -M -O/dev/null --end-of-options <base> --`, then `ls-files --others --exclude-standard -z`, both on one private index; kinds `added`, `modified`, `deleted`, `renamed` (with `old_path`), `type_changed`, `untracked`.
- **`history.lua`** — GH3: `log -z --format='%H %s' --no-show-signature --encoding=UTF-8 --ignore-missing --end-of-options <base>..HEAD --` and `merge-base --is-ancestor` (exit 1 an answer).
- **`diffs.lua`** — GH4, GH5: the unified-diff flags `--no-color --no-ext-diff --no-textconv --src-prefix=a/ --dst-prefix=b/ --unified=3 --inter-hunk-context=0 --find-renames --full-index -O/dev/null`; an untracked file through `diff --no-index -- /dev/null <path>` (exit 1 with a diff an answer; exit 1 with none is git failing to read the file, a failure in git's words); a rename asked with both paths; `show` with `--root --pretty=medium --no-abbrev-commit --no-decorate --no-notes --date=default --encoding=UTF-8 --no-show-signature`.
- **`private_index.lua`** — GH8: both diffs, and the list's untracked files, run with `GIT_INDEX_FILE` pointing at a copy of the index in Neovim's temporary directory, stamped with the real index's modification time (taken before the copy), removed (with any `.lock` beside it) when the read ends; a missing index is an empty one; an index that cannot be copied is a failure. The copy's name is taken on the main loop, so the reads can be asked for from a fast event.
- **`watch.lua`** — GH9: a watch on the top level (events in `.git` set aside) and one on the common git directory, recursive where libuv watches recursively (`Darwin`, `Windows_NT`, from `vim.uv.os_uname().sysname`, which a caller may replace as `system_name`); a burst ends 200 ms after its last event or 1 s after its first; a burst that touched the git directories reads `HEAD` again and compares commit and branch; an event naming an index (`index`, `*/index`) or a submodule's file (`modules/*`) counts as a change of the list, `files_changed`. An error libuv passes to a watch's callback reaches `on_change` as a failure. Reads are serialized; `stop()` cancels one in flight, releases every handle, and does nothing the second time.

Tests: `tests/test_git_repository.lua`, `test_git_process.lua`, `test_git_changes.lua`, `test_git_commits.lua`, `test_git_diffs.lua`, `test_git_configuration.lua`, `test_git_lock.lua`, `test_git_watch.lua`, and `tests/helpers/git_repo.lua`. Every case runs the home in a child Neovim whose environment carries `tests/helpers/git.lua`'s `HERMETIC_ENVIRONMENT` and `GIT_CEILING_DIRECTORIES=<checkout>/.tests/fixtures`; every fixture is `.tests/fixtures/git-<name>`.

## Decisions

- **GH8's mechanism: a private copy of the index**, over `-c diff.autoRefreshIndex=false`, which lists every stat-dirty file as modified (the brief review's finding 1). Pinned twice: `.git/index`'s inode, size and mtime unchanged after a read over three stat-dirty files; and a watch on `.git` that starts a `git commit` the moment `index.lock` appears, then a marker file whose event ends the watch — no lock is ever seen. Against the repository's own index both cases fail (mutants CH4, DF17). The fix round stamped the copy with the real index's modification time (attack 1): a copy stamped with the time it was made defeats git's racy-clean check, and a file rewritten at the same size within the second its index was written was missing from the list. `GIT_OPTIONAL_LOCKS=0` also does work of its own: without it a read rewrites a submodule's index (attack mutant M1, pinned in the fix round), so it is not equivalent, as the test-integrity review had it.
- **What a list change is, for the watch (the orchestrator's decision in the fix round, attack 7):** an index write, and any change of a submodule's, counts as a change of the list, `files_changed`. So `git add`, `git rm --cached`, a staged rename and a submodule's moved branch call back; and a commit, which always writes the index, now reports `files_changed = true` too, even one that changes no file. The over-report is accepted: T25 re-reads the list, and nothing is lost. Four cases changed their expectation from `files_changed = false` to `true`: the empty commit, the commit after `git gc`, the first commit, and a linked worktree's commit. The watch's test for an index is the attack review's measured one — `index` and `*/index`, so another worktree's index write calls back too — not one narrowed to this worktree's index, which no case could tell apart.
- **GH7 by flags, never by switching the user's configuration off** (the brief). Two departures from the brief's measured set, each measured: `--src-prefix=a/ --dst-prefix=b/` for `--default-prefix` (git 2.41), since the older pair neutralises `diff.noprefix` and `diff.mnemonicPrefix` the same way; and no `--no-relative`, since every command runs at the top level, where `diff.relative=true` changes nothing (the hostile cases run from a subdirectory and pass).
- **`--end-of-options` before the revisions of `diff`, `log` and `show`**: a base or commit that reads as an option — `--output=<file>` — is refused and writes nothing. Not in the brief; found while writing GH5, since `git show --output=<file>` writes a file. `merge-base` has no such option and fails on one either way, so it has none: the author removed the token after mutant H8 survived, a removal that is the author's, not a review's.
- **The watch compares `HEAD`, it does not trust an event** (the brief review's finding 2): a watch on the whole common directory rather than on `logs/HEAD`, so a reflog replaced by `gc` or `reflog expire`, a repository with no commit yet and an `update-ref` from another worktree are all seen.
- **Failure shape**: `{ reason, message, code? }`, `reason` one of `not_a_repository`, `no_git`, `timed_out`, `failed`.

## Limits

Each is also said where a caller meets it, in the docstring named.

- **Linux's watch** (attack 10, records 6; `init.lua`'s `watch_repository`, `watch.lua`'s `Watch.watches_subdirectories`). libuv takes the recursive flag on Linux and watches each directory alone. As measured on macOS through libuv's non-recursive path (Linux itself was not run): the watch misses a file changed in a subdirectory and a branch moved by `git update-ref` from another worktree; it sees a commit (the index and `COMMIT_EDITMSG` sit in the common directory), a `reset --soft` (`ORIG_HEAD`, written there directly) and a linked worktree's commit (through `packed-refs.lock` at the top of the common directory, not through that worktree's index, which sits in a subdirectory). The packet's earlier reading that a `reset --soft` is missed there was wrong.
- **A change made as a watch starts** can be missed: on macOS libuv starts its event stream on a thread of its own after `start()` returns. 2 of 50 writes made right after two watches started were never reported (`t23f-probe-live-0125.txt`, load 47) (`init.lua`).
- **Diff size is not bounded** (attack 16; `init.lua`'s module docstring): a commit adding a 100 MB file gives a 100 MB diff. T25 decides what to show.
- **The private copy never keeps git's refresh** (attack 17; `private_index.lua`): a repository whose tracked files all changed stat — rewritten with the same content — makes every read hash every file again until a git of the user's or Claude's refreshes the real index; the attack review measured 60 000 such files timing out at 10 s.
- **A cancel cannot hold back `done(no_git)`** (records 7; `process.lua`'s `run_git` and `aineo.git.Run`, `watch.lua`'s `read_branch` and `Watch.stop`): when git cannot be started, the cancel does nothing, so a watch stopped in the main-loop turn its read of `HEAD` found no git calls `on_change(no_git)` once after `stop()`.
- **A descendant of git that starts a process group or a session of its own** escapes the limit's kill (`process.lua`'s `kill`).
- **An error libuv passes to a watch's callback** is reported as a failure (attack 15), reasoned from libuv's `fsevents.c` (the error of a stream it could not start again is given to every watch of the loop), not provoked: no case reaches it, and no mutant was run on it.
- **A stamp that fails** after the copy was made: the copy is removed before the failure is reported. No case reaches it.
