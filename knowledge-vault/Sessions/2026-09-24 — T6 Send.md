## What was done

**`lua/aineo/send/init.lua`** — a new home, one export, `send()`, requiring `aineo.claude` and `aineo.layout` through their entry points (the direction table allows both). It reads Input (`layout.input_buffer()`), joins its lines with line feeds, removes every byte that can open a control sequence, and — when the result holds more than white space and `claude.session_status()` reads `'ready'` at that moment — writes `ESC[200~` text `ESC[201~` `\r` in one write, then empties Input with `nvim_buf_set_lines`, which keeps the buffer and its options. Otherwise it writes nothing, keeps Input, and gives one `vim.notify` warning naming the reason.

**`lua/aineo/claude/init.lua`** — one new export, `write_to_session(bytes)`: `nvim_chan_send` to the session's job, raising `aineo.claude: no Claude Code session is running to write to` unless the session runs as `start_session()` counts it (`is_running()`: process alive and terminal not wiped). Nothing else in the file changed.

**Tests** — `tests/test_send.lua` (19 functions, one parametrized two ways: 20 cases), five new cases in `tests/test_claude.lua` (four for `write_to_session()`, one `session_status()` case on the turn screen); helpers `tests/helpers/send.lua` (a 240×42 child, notifications and errors `send()` raises kept as messages, the layout opened around the session's terminal in the same tick as `start_session()`), and in `tests/helpers/claude_session.lua` two new helpers, `received()` and `wait_for_received_after()`, which join the fake's chunks after a byte offset so a case compares exactly what arrived after the send. The fake gains the mode `turn` (screen B of `t6-summary.txt`, answering Ctrl-C as in a turn), its fixture `tests/fixtures/claude/turn-2.1.281.screen` with a header naming its source.

## Decisions & reasoning

- **Remove every escape byte, then every U+009B until none is left** (SD7). Removing the escape byte leaves no `ESC[201~` and no nested form to rebuild one: the brief review's `ESC[20ESC[201~1~` and `ESC ESC[201~[201~` both arrive as plain text. U+009B (C1 CSI, `C2 9B`) is removed too, repeatedly, since `C2 C2 9B 9B` becomes `C2 9B` after one pass. A lone `9B` byte is left alone: it is a continuation byte of many characters (`😛` is `F0 9F 98 9B`), and an invalid lone one is decoded by a UTF-8 reader as U+FFFD, not as CSI — unmeasured on Claude Code.
- **Empty is judged on the text Send would paste** — after that removal — so an Input of escape bytes and blanks does not send an empty paste whose Enter would submit a draft in Claude's box (the second commit, seen red first).
- **One write, never split** (SD8). A text of 103,423 bytes (1,024 lines of 100 bytes) reached the fake byte for byte after one `nvim_chan_send`: the whole write, 103,436 bytes with the markers and Enter, arrived as 102 chunks of at most 1,022 bytes (the pty's reads), in order, the Enter in the last (`.tests/fixtures/claude-send-long/record.jsonl`, Nvim 0.11.6, macOS). Splitting would add nothing the kernel does not already do, and one write is what the orchestrator measured on the real CLI (23,716 bytes, `t6-summary2.txt` (b)); a 100 KiB text was not measured on the real CLI.
- **Status read last, just before the write.** The checks run in the order Input exists, Input not empty, session ready, so the status that decides the write is read in the same tick as the write.
- **`write_to_session` raises instead of returning a flag** — `send()` never calls it without `'ready'`, which implies a running session in the same tick, so a call on a stopped session is a caller's error; it raises its own message rather than `chansend()`'s "Can't send data to closed stream".

## Readings for the MVP review

1. **The empty-Input rule** — Input is empty when the text Send would paste (lines joined by `\n`, control-sequence bytes removed) holds only Lua `%s` white space (space, tab, CR, LF, VT, FF); a non-breaking space counts as text. Pinned by the empty, blank-lines and escape-bytes cases.
2. **No Input** — before the layout first opened, and once Input was wiped, are one case: "aineo: nothing sent — there is no Input; open aineo’s layout to make one" (`layout.open()` makes a new Input then).
3. **`vim.notify` at `WARN` is the channel of every refusal**, once per refusal, and the wording: `aineo: nothing sent — Input is empty`; `… — Claude has not started`; `… — Claude is not ready: it is starting, or a dialog in its window awaits your answer`; `… — Claude has exited`; the no-Input message above.
4. **Send onto a draft** — Send writes only its paste and Enter; the draft Claude's box already holds is left as it is, and the paste joins it; since a paste lands in the box and Enter submits the box (Q1), Claude Code should submit draft and paste as one message — inferred, not measured with a draft on the real CLI. Pinned on the fake's `draft` mode: the bytes after the send are exactly the paste and Enter, no Ctrl-C.
5. **What Send does to the text** — removes escape bytes and U+009B (above); keeps every other byte, CR inside a line included; does not trim leading or trailing blank lines.
6. **C1 form** — whether Claude Code ends a paste on `C2 9B 201~` was not measured; Send removes U+009B regardless.
7. **During a turn Send sends** (D14) — pinned on the new `turn` mode: the session reads `'ready'` and Send's bytes arrive.

## Limits

- **R4, accepted with D14** — the session turns `'starting'` 10.8 to 29.5 ms (ten cycles) after a permission dialog's bytes reach the terminal (the re-measure of PR #11, finding 8). A Send inside that window writes its paste and Enter into the dialog; by the dialog's footer ("Enter to confirm") the Enter would pick its highlighted `❯ 1. Yes` — inferred, not measured; what the dialog does with the pasted bytes is unrecorded. The send path does not close this.
- **A second Send soon after a first may be refused by Claude Code's own redraw**: a redraw of the input box reaching the terminal in two writes 20 ms or more apart turns the session `'starting'` for about 1.5 s (the settle). The fake cannot show this — its echo is not Claude Code's redraw (it overwrites the box's lower rule, so a second send to the `ready` fake reads `'starting'` from then on); every case that expects a send's bytes sends once, on a fresh session (the dialog case's second send is refused by design).
