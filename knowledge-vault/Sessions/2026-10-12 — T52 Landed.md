## What was done

The commits that merged into the working branch while the session ran (an orchestrator's agents work in worktrees of their own and land by pull request) show in the commits window under a `Landed in <name>` heading, each a filter, with their combined change as the heading's filter (D56; the user's U1 (a) and U2 (a)). The orchestrator's rulings A136–A157 (O1–O16, A3 as A156) are its assumptions under the user's instruction of 2026-10-06, not the user's decisions.

- **`changes.working_branch`** (`lua/aineo/config/init.lua`): a non-empty string, no default. The resolved defaults gain an empty `changes = {}`. `plugin/aineo.lua` hands it to `begin_session()` as `working_branch`; `aineo.changes` reads no configuration.
- **`lua/aineo/changes/landed.lua`** (new): the name (the setting, else `git.remote_default_branch()`, else none), the commit it names once (`git.resolve_commit()`), then `git.commits_between(base, tip)`. A failed read answers its failure with what the window knew before. `unreadable()` is the failure for a name that names no commit.
- **`filter.lua`**: a `landed` kind and a `landed` field (the branch's name) on a commit filter; keys `\0landed` and `\0landed\0<id>`, so a commit listed among the session's and among what landed is two entries.
- **`lines.lua`**: the section between the editor's own rows and the other worktrees' (`landed_rows()`); `commit_rows()` takes a function that gives each commit its filter; `Landed in <name>` as the filter's name; `No files changed in what landed`. The name is quoted as a path is.
- **`init.lua`**: `read_landed()` runs beside the commits read (not inside it, so the session's own list shows as soon as before; a stale answer is dropped by a counter and `is_current_base()`; an answer equal to what the window knew writes nothing); `take_landed()` reselects Session work for a landed commit no longer listed or a section no longer shown (A97) and reads the files window again when the heading is selected and the branch names another commit; `follow_change()` reads the commits for `references_changed`; `read_for_new_base()` forgets what landed; files under the heading are `git.files_between(base, tip)`.
- **`entry_diff.lua`**: `aineo://landed`, `aineo://landed/{path}` (`diff_between`, `file_diff_between`); a landed commit uses the session's commit names (O14).
- **`doc/aineo.txt`**: *aineo-changes* (first line, the files under the heading, the choices, the section, Enter, the reads again, a failed read), *Colours*, `hl-AineoChangesFilter`, the config item with two tags, LIMITS (a bullet on never fetching, the base not behind the branch, a checkout on the working branch, unrelated histories, a dangling default branch, the cost; the Linux bullet). Corrected: the sentences these made false (the list of what a files choice is, the order of the reads, the sentence on the one read at a time).

## Decisions

- Landed is read beside the commits read, so the session's own list is not delayed (above).
- A failure of the default-branch, resolve or log read keeps what the window knew and is told in the editor's own failure line (`session.landed_failure`), not in a line under the heading.
- Unrelated histories: git's words, no special wording (recommended in the amendment; the orchestrator rules at the review).
- `tests/test_doc.lua` is not mine; the second tag is unchecked (above).
