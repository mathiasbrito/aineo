## What changed beyond a move

- **The plugin file calls the home lazily**, as it calls every home: each callback `require('aineo.entry')`s. `:Aineo` checks its argument against `ACTION_ARGUMENTS` before loading the home, so a wrong argument loads nothing, as before; the Visual `send` mapping calls `send_visual_selection()`.
- **`run()` is split.** The plugin file's `run()` loads `aineo.entry` only when the action raised (`tell_error()`), so that a headless start still loads `aineo.config` alone (`tests/test_plugin.lua`); `entry/errors.lua` has the same `run()` over the same `tell_error()`.
- **`resolved_config()` is in two files**, the plugin file (the keys and the autostart at startup) and `entry/tab.lua` (each action): two lines reading `vim.g.aineo`, which only a composition root may read.
- **A restored session** (`v:this_session`) clears the first open's reopening through `forgo_tab_reopening()`, which loads `aineo.entry` on that start; before, it cleared a local of the plugin file.
- **`make_tab(homes, key, callbacks)`** takes `aineo.entry.TabCallbacks` — `on_bound` (was the third argument) and `open_new_tab` — since `tab.lua` cannot require `opening.lua`, which requires it; `opening.lua`'s `tab_callbacks()` builds it.
- **The tab used last is `registry.last_used_tab`**, a field the files set; `tab_list` is the same table for the editor's life.
- **`folder_tabs.while_reopening(reopen)`** runs the reopening with the list kept by none of the tabs it opens, in place of `reopen_folder_tabs()` setting another file's flag.
- **Docstrings** that named `ACTION_ARGUMENTS` or `open_unless_session_restored()` from moved code now say what they mean; the draft home's two docstrings name `aineo.entry` as the caller that hands it Input.
