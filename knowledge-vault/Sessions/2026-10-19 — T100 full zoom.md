# 2026-10-19 — T100 full zoom

**Author:** the repository's maintainer, with Claude — implementer agent (`neovim-lua-developer`, on Sonnet)
**Branch:** `feature/t100-full-zoom` · **Pull request:** into `dev`

`\Z` zooms the window the cursor is in to the whole tab page: every other window shrinks to the least size Neovim allows and stays open as a sliver; `\Z` again gives every window the size it had. A regular packet in wave 21 of the user's prompt-driven waves (D26 applies).

## Design

- **A module of its own.** `lua/aineo/layout/full_zoom.lua` beside `zoom.lua`, one concern: the sizes of a tab page's windows while one is zoomed. `start()` records every window's width and height and the editor's size, then asks the zoomed window for the screen's whole width and height; Neovim takes the cells from the others down to their least. `keep()` asks again. `restore()` sets every recorded window's size in two passes (setting one window moves its neighbours), scaled by the editor's extent when it changed since. `zoom.lua` could not be reused as it is: it is height-only over one column, so the full zoom shares its idea, not its code.
- **State and triggers stay in the layout.** `state.full_zoom`, `end_full_zoom()` and `keep_full_zoom()` in `layout/init.lua`: `switch_pane()` and `sync_run_windows()` end it (restoring) before they end the column zoom; `apply_proportions()` keeps it in place of every proportion (resize, `TabEnter`, a closed window), or drops it without restoring when the zoomed window is gone; `equalize_run_windows()` leaves a fully zoomed stack alone; `toggle_zoom()` ends it first, after its own refusal check, so a `\z` that refuses leaves the full zoom as it is.
- **`\z` interplay.** The full zoom records the sizes the column zoom left, so ending it gives the column zoom back exactly, and the column zoom's own record is untouched: the next `\z` gives the heights from before it.
- **Refusal.** `toggle_full_zoom()` warns once, `aineo: nothing zoomed — the cursor is in no window of an aineo tab page, or in a floating window`, when the layout has no window, the cursor is in another tab page, or in a floating window.
- **Entry.** `:Aineo zoom` takes the word `full`: `plugin/aineo.lua` gives `zoom` a word list and `ACTS_WITHOUT_A_WORD`, so `zoom` and `zoom full` are both actions, the key `Z`, the `<Plug>` mapping, the terminal twin and the health check's key list follow from the tables. A wrong word after `zoom` now reports `aineo: :Aineo zoom takes one of full`, as `pane` and `diff` report theirs, where it reported the generic usage.

## Decided against the brief

A509 says `'winfixwidth'` and `'winfixheight'` are set aside during the zoom. Not followed, on measurement (Neovim 0.12.5, headless):

- Neovim shrinks fixed windows anyway when a window asks for more than the screen holds: the layout's windows (all pinned by `pin_windows()`) and a quickfix list with `'winfixheight'` went to their least size, and came back exactly (pinned by `shrinks the layout’s fixed windows and a quickfix list across the tab page…`). The T93 note measured the same for heights.
- With the flags set aside on every window of the tab (the experiment: `vim.wo[window].winfixwidth = false` in `start()`), entering a sliver takes `'winwidth'` (20) columns from the zoomed window, which breaks D90's "moving the cursor elsewhere keeps it": the case `moving the cursor while zoomed fully | keeps the zoom on the window that was zoomed` failed with `left = 20, right = 1`; every other case passed. A window split by hand has no pin and takes those columns on entry anyway (measured: 1 to 20), which the help says.

The flags stay as they were; `leaves ’winfixwidth’ and ’winfixheight’ as they were, zoomed and after` pins that.

## Limits and open threads

- A window split by hand and fully zoomed away takes `'winwidth'` columns on entry; aineo's pinned windows keep theirs (help, *aineo-zoom-full*).
- A window opened while the zoom is on (a file redirected to the file column, say) is not in the recorded sizes: it takes what Neovim gives it, and the zoom is asked again at the next proportions step. The brief's triggers do not include it.
- Restoring after a resize scales each recorded size by the editor's extent and lets the last window of each row and column take the rest; the sum of a column's heights is exact, an individual window can differ by a cell from a proportional share (pinned on the sum and the first column).
- `\Z` in the terminal pane's one window zooms it across the tab page; nothing is special-cased.
