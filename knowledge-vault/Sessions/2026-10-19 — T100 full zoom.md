# 2026-10-19 — T100 full zoom

**Author:** the repository's maintainer, with Claude — implementer agent (`neovim-lua-developer`, on Sonnet)
**Branch:** `feature/t100-full-zoom` · **Pull request:** into `dev`

`\Z` zooms the window the cursor is in to the whole tab page: every other window shrinks to the least size Neovim allows and stays open as a sliver; `\Z` again gives every window the size it had. A regular packet in wave 21 of the user's prompt-driven waves (D26 applies).

## The user's words

"plan also a full zoom feature also", and the three recommended options chosen: the key `\Z` (also `<C-\>Z`, `:Aineo zoom full`, `<Plug>(aineo-zoom-full)`), the mechanism "shrink to minimum" with the other windows alive and visible as slivers, and the auto-end as `\z` does.

## Design

- **A module of its own.** `lua/aineo/layout/full_zoom.lua` beside `zoom.lua`, one concern: the sizes of a tab page's windows while one is zoomed. `start()` records every window's width and height and the editor's size, then asks the zoomed window for the screen's whole width and height; Neovim takes the cells from the others down to their least. `keep()` asks again. `restore()` sets every recorded window's size in two passes (setting one window moves its neighbours), scaled by the editor's extent when it changed since. `zoom.lua` could not be reused as it is: it is height-only over one column, so the full zoom shares its idea, not its code.
- **State and triggers stay in the layout.** `state.full_zoom`, `end_full_zoom()` and `keep_full_zoom()` in `layout/init.lua`: `switch_pane()` and `sync_run_windows()` end it (restoring) before they end the column zoom; `apply_proportions()` keeps it in place of every proportion (resize, `TabEnter`, a closed window), or drops it without restoring when the zoomed window is gone; `equalize_run_windows()` leaves a fully zoomed stack alone; `toggle_zoom()` ends it first, after its own refusal check, so a `\z` that refuses leaves the full zoom as it is.
- **`\z` interplay.** The full zoom records the sizes the column zoom left, so ending it gives the column zoom back exactly, and the column zoom's own record is untouched: the next `\z` gives the heights from before it.
- **Refusal.** `toggle_full_zoom()` warns once, `aineo: nothing zoomed — the cursor is in no window of an aineo tab page, or in a floating window`, when the layout has no window, the cursor is in another tab page, or in a floating window.
- **Entry.** `:Aineo zoom` takes the word `full`: `plugin/aineo.lua` gives `zoom` a word list and `ACTS_WITHOUT_A_WORD`, so `zoom` and `zoom full` are both actions, the key `Z`, the `<Plug>` mapping, the terminal twin and the health check's key list follow from the tables. A wrong word after `zoom` now reports `aineo: :Aineo zoom takes one of full`, as `pane` and `diff` report theirs, where it reported the generic usage.

## Decided against the brief

The orchestrator's A509 said `'winfixwidth'` and `'winfixheight'` are set aside during the zoom. Not followed, on measurement (Neovim 0.12.5, headless):

- Neovim shrinks fixed windows anyway when a window asks for more than the screen holds: the layout's windows (all pinned by `pin_windows()`) and a quickfix list with `'winfixheight'` went to their least size, and came back exactly (pinned by `shrinks the layout’s fixed windows and a quickfix list across the tab page…`). The T93 note measured the same for heights.
- With the flags set aside on every window of the tab (the experiment: `vim.wo[window].winfixwidth = false` in `start()`), entering a sliver takes `'winwidth'` (20) columns from the zoomed window, which breaks D90's "moving the cursor elsewhere keeps it": the case `moving the cursor while zoomed fully | keeps the zoom on the window that was zoomed` failed with `left = 20, right = 1`; every other case passed. A window split by hand has no pin and takes those columns on entry anyway (measured: 1 to 20), which the help says.

The flags stay as they were; `leaves ’winfixwidth’ and ’winfixheight’ as they were, zoomed and after` pins that. The orchestrator then ruled it as A510.

## Fix round 1 (the attack and test-integrity reviews of PR #288, and the orchestrator's A512)

Each case below was seen red on the head the reviews measured, with the tests of the round on that head's code, before the code changed.

- **`'cmdheight'` grew on unzoom** (attack 1): a window that spans the tab page's height, Claude's and the file column's, cannot take rows from a neighbour, so setting its height shrinks the top frame and `'cmdheight'` takes the rows. `full_zoom.lua` now never sets the height of such a window (`spans_tab_height()` over `winlayout()`), in `take_every_cell()` and in `restore()`; the attacker's sketch put `'cmdheight'` back after the resize instead, which changes it twice, and A512 forbids changing it at all. Red: `…the command line one line high` at 31 lines (`cmdheight` 2) and at 48 (3); at 30 it passed, which is why the case ran only there before.
- **A window opened during the zoom** (attacks 2 and 3): `end_full_zoom()` restored the recorded sizes whatever happened, squeezing the new file column to one column and the quickfix list to one line. It now restores them only when the tab page holds the windows it held (`vim.deep_equal` of the tiled windows), and puts the layout's proportions back otherwise. Red: the file column, the quickfix list and the split of the zoomed window (`left = 1, right = 11`).
- **The zoomed window of the layout closed** (attack 4): the layout is not open then, so `keep_proportions()` did nothing and Claude stayed one column wide. `keep_proportions()` now ends a full zoom whose window is gone first; with the layout not open, the windows that remain get their recorded sizes. Red: Report and Input (`left = 1, right = 40`).
- **A pane change without `switch_pane()`** (attack 5), probed with cases before any change: the wipe of the shell's terminal under the terminal pane (`show_agent_pane_as_shell_is_wiped()`) and `forget_wiped_shell()`, reached by `open()` when the wipe ran no handler (`eventignore`), both left Claude 78 columns wide with the agent pane shown. Both now end the zoom. Red: both.
- **Eleven cases passed with `\Z` doing nothing** (tests 1): each now asserts the zoomed width after its first toggle (`expect_zoomed()`), and the cursor case compares the zoomed sizes with those before. Under `if false and zoomed ~= current then` in `toggle_full_zoom()`, 42 of the 51 cases fail, among them those eleven; they pass on the head.
- The scaled-restore case runs at 30, 31 and 48 lines and asserts `'cmdheight'` stays 1 and Claude holds every row that fits.

## Limits and open threads

- A window split by hand and fully zoomed away takes `'winwidth'` columns on entry; aineo's pinned windows keep theirs (help, *aineo-zoom-full*). The attack review suspected `:split` copies `'winfixwidth'` from a pinned window: measured, a `:split` of Claude's window has `winfixwidth` and `winfixheight` false, and a `:vsplit` of it went from 1 to 20 columns on entry, so the help line stands.
- A window opened while the zoom is on (a file redirected to the file column, the quickfix list, a split) is as small as the zoom leaves it until the zoom ends; ending then puts the layout's proportions back (A512).
- Not probed: `take_arrangement()` sets the pane from the run pane to the agent pane when an arrangement hands no run terminals, which also changes the pane without `switch_pane()`.
- Restoring after a resize scales each recorded size by the editor's extent and lets the last window of each row and column take the rest; the sum of a column's heights is exact, an individual window can differ by a cell from a proportional share (pinned on the sum and the first column).
- `\Z` in the terminal pane's one window zooms it across the tab page; nothing is special-cased.
