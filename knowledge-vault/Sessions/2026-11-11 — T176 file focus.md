## What

`<C-l>` in the explorer (the `\E` column and the `\e` pane) shows the file under the cursor as `l` does and turns the file focus on for the tab: the panes column (Report, Input and the pane shown, the run pane's stack included) closes and its cells go to the file column, the row being Claude | files | explorer, mirrored with Claude on the right. Every file opened while it lasts keeps the panes column closed. `<C-l>` again on any line, `:Aineo focus` or `<Plug>(aineo-focus)` bring the column back as it was. A key that shows a pane ends the focus. No default key outside the explorer.

- `lua/aineo/layout/init.lua` owns the state: `start_file_focus()`, `end_file_focus(arrangement)`, `is_file_focused()`; `M.open()` ends the focus; `is_laid_out()` lets the proportions, the explorer column and a file column opened meanwhile be kept while the panes column is closed on purpose; `size_focused_columns()` keeps Claude's and the explorer's widths and gives the file column the rest.
- `lua/aineo/explorer/home.lua`: `<C-l>` through the optional settings `is_file_focused` and `toggle_file_focus`; `lua/aineo/entry/explorer.lua` hands them (the tab found by its homes); `lua/aineo/entry/tab.lua` and `actions.lua`: `actions.focus` and `:Aineo focus`; `lua/aineo/entry/run_pane.lua`: an ended process is not discarded when the focus closes its window, and a process leaving does not end the focus.
- Registration: `plugin/aineo.lua` (`focus` after `zoom`), `lua/aineo/keys/init.lua` (the explorer row). Docs: `doc/aineo.txt` (File focus section, `:Aineo-focus`, `<Plug>(aineo-focus)`, the explorer key list, the prefix-keys sentence), `README.md`.

## Decisions (point 6 of the brief)

- Closing the file column, with the focus applied, brings the panes column back and leaves the focus armed (A739.1; the first version left it on with the panes column closed).
- A zoom, of the panes column or full, ends as the focus starts (sizes not given back); `\z` with the focus on says the cursor is in none of the panes column's windows; `\Z` works on any window.
- `M.open()` ends the focus, so a session start, a resume and `setup()` re-applying the explorer column setting end it too; `\E`, a swap, a mirror and an editor resize keep it.
- `<C-l>` closing the explorer *pane* closes the pane with the column; the cursor goes to the file.

## Fix round after the attack review of #420 (A739)

- **A739.1** (the user's ruling through the coordinator): with no file column the focus is *armed*, not applied. The panes column stays and nothing widens; the next file opened in the tab applies it (`keep_proportions()` applies an armed focus once a file column is open), the file column taking the panes' width; closing the file column of an applied focus brings the panes column back (`restore_panes_column()`) and leaves the focus armed. Claude's and the explorer column's widths never change through focus; Claude's width is the one it has while the focus waits (refreshed at each proportions pass), so no size reaches its pty. `is_file_focused()` is true for an armed focus, so `<C-l>`/`:Aineo focus` end it.
- **A739.2**: only the user's own pane keys and commands end the focus. The agent's run tool (`start_in_run_stack`, the MCP `run`) starts its process hidden while the focus is on, as the walkthrough-plan tool leaves it. The MCP answer's text still says the pane is brought into view; it is left as it is (an exact string under test).
- `\E` after a focus started from the explorer pane: `set_explorer_column` sets `state.pane = 'agent'` instead of `switch_pane('agent')` while the focus is applied (measured fix of the attack review).
- Views: the Report's and Input's windows' views are saved as the focus applies and restored after the proportions in `M.open()` and in `restore_panes_column()`, a report that arrived meanwhile winning; the explorer pane's cursor comes back with them.
- The `vim.schedule` in the explorer's `<C-l>` stays: toggling at once saves the explorer pane's view before `return_cursor_to_tree()` has put its cursor back (mutant E3, killed by the explorer-pane cursor case). A mutant that removes `M.open()`'s view restore survives at entry level, where the explorer's own re-read keeps its cursor, and is killed at layout level (the Report's view).
- Test integrity: each pane-key case now asserts the windows of the pane that comes back and where the cursor lands.
