Reading:
- A tab page's handle is stable for its life, through `:tabmove` and the
  closing of other tabs. Its number is its place and changes with both.
- `TabClosed` gives the closed tab's *number* in <afile>, and its handle is
  already invalid there. Code that keeps state per tab finds the closed one
  by checking each handle it holds with `nvim_tabpage_is_valid()`.
- A terminal job keeps running when the tab that showed it closes: its
  buffer is only hidden. Closing a tab by any means leaves its Claude Code
  running unless aineo stops it.
- The last tab page cannot be closed (E784).
- `{n}gt` past the last tab does nothing and raises nothing. `:tabnext {n}`
  past it raises E475.
- `:tcd` gives a tab its own working directory, so `getcwd()` differs
  between tabs. A start that takes `getcwd()` could start in another folder.
- Neovim's 'tabline' is empty by default, and 'showtabline' is 1: the line
  shows only with two tabs or more.
- A second buffer cannot take a name another buffer holds (E95). So a second
  Report or Input made under today's fixed names fails.

== P2: what a second Claude Code in one editor would share (read)
- aineo hosts no IDE connection. No lock file, no WebSocket server, no `/ide`
  support exists under `lua/`, `plugin/` or `doc/`. The only lock is the
  process record's (`lua/aineo/mcp/processes.lua:138`). So two Claude Codes
  in one editor share no IDE lock file, because there is none.
- The report server is per Claude Code. Each start passes its own
  `--mcp-config`, made by `aineo.mcp`'s `mcp_servers(vim.v.servername,
  vim.v.progpath)` and `with_start_token()` (`lua/aineo/mcp/init.lua:27`,
  `:49`). Claude Code runs it as its own child (`nvim --headless --clean -l`).
  It finds the report's session from the record of its own Claude Code
  process, by pid and start token (`delivery.lua`'s `report_session()`).
- The session hook relay is per hook run. It calls
  `require('aineo.claude').receive_session_event(...)` in the editor
  (`hook_relay.lua:62`) with the start token. The claude home drops a hook
  whose token is not the token of its one start (`take_session_event()`,
  `claude/init.lua:1138-1142`). With one start per tab, the token names the
  tab's Claude Code.
- What one editor has once: its server address (`v:servername`), and its
  one entry in the list of running editors, one file per address
  (`editors.lua:34`, `entry_file()`). That entry holds one `session`.
  Delivery offers a report to each listed editor whose `entry.session` is
  the report's (`delivery.lua:151`).
- What the editor runs for a report is
  `require('aineo.report').receive_session_report(report, session, options)`
  (`delivery.lua` `RECEIVE_SESSION_REPORT`, `RECEIVE_AT_START`). Its
  `options` is a table (`AT_START`, `KEEP_WITH_DIRECTORY`). An older editor
  ignores a key it does not know there.

== P3: the stop at quit, one Claude Code after another (computed)
`lua/aineo/claude/stop.lua`: KEY_PRESSES waits 2500 + 300 + 4000 ms, then a
hangup waits up to EXIT_AFTER_HANGUP_MS 5000 ms. That is 11.8 s at worst per
Claude Code, all of it blocking the editor (`wait_for_exit()`). Claude Code
2.1.281 exited 1.6-2.5 s after the second Ctrl-C (the constants' docstrings),
so about 4.4-5.3 s each in the usual case. A quit that stops N Claude Codes
one after another blocks N times that: about 18-21 s for four tabs, 47 s at
worst. A stop that presses each key to every terminal and shares the waits
takes about one stop's time. `stop_on_quit()` (`claude/init.lua:92`) makes
its `VimLeavePre` handler in the group `aineo.claude`, which
`nvim_create_augroup(…, {})` clears: a second registration replaces the
first.

== P6: the session list at a start (read)
`claude/agents.lua`: `list_sessions(command, folder, on_done)` runs
`claude agents --json`, bounded at LIST_BOUND_MS 5000 ms (`:19`, `:343`).

== P7: the session list's rows (read)
`agents.standing()` gives `own` for the session of aineo's terminal, and
`elsewhere` for any session another process runs. So another tab's Claude
Code of this editor would read as `[running elsewhere]`
(`STANDING_MARKS`, `claude/agents.lua:168`). A pick of it would then attach
or resume it (D62) in a second terminal of the same editor.

== P8: the folder (read)
`plugin/aineo.lua`'s `kept_places()` takes `getcwd()` the first time it is
called and keeps it. `started_claude_terminal()` takes `vim.fn.getcwd()` at
every start. With `:tcd` (P1), two tabs' starts could start in two folders.
