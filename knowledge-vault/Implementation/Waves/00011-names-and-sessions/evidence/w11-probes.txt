P5 — what `←` does in Claude Code (read, never run)
---------------------------------------------------
The installed Claude Code is 2.1.296 (the version directory the `claude`
link on the host's PATH resolves to; `claude` itself was not run). Read raw:
`https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md`
(top entry `## 2.1.296`) and `https://code.claude.com/docs/en/agent-view.md`,
`https://code.claude.com/docs/en/interactive-mode.md`, fetched 2026-10-11.

agent-view.md, *Switch sessions without leaving the terminal*:
  "In a session running in the foreground, one you started in the terminal
  rather than attached to from agent view, pressing `←` on an empty prompt
  backgrounds it and opens agent view with that row selected, so you can
  switch sessions without leaving the terminal."
  "If you press `←` right after you delete the last of the prompt's text or
  move through prompt history, Claude Code asks you to confirm: the first
  press shows `Press ← again to open agents` [...] and the second press
  switches."
  "Press `Esc` to undo the switch and return to the conversation."
  "You type into the prompt input: Claude Code cancels the switch [...]
  `Backgrounding cancelled — you have unsent text in the input.`"
  "You can turn this shortcut off for foreground sessions with the
  [`leftArrowOpensAgents`] setting in `/config`."
agent-view.md, *What carries over when you background*:
  "Backgrounding starts a fresh process that resumes from the saved
  conversation [...]"
  "Configuration flags from the original launch carry through to the
  backgrounded session [...]: `--mcp-config` and `--strict-mcp-config`,
  `--settings`, `--setting-sources`, `--add-dir`, `--plugin-dir`,
  `--fallback-model`, `--allow-dangerously-skip-permissions`" — the list
  names neither `--append-system-prompt` nor `--allowedTools`, which aineo
  passes (C3, D11), nor the environment (`AINEO_CHILD`, the editor's
  address, C3).
agent-view.md, the walkthrough: "Press `Enter` or `→` on a row to attach
  [...] The session takes over the terminal as a full interactive Claude
  Code session. Press `←` on an empty prompt to detach and return to the
  table." *The supervisor process*: "Each session is its own Claude Code
  process under the supervisor". "An attached session doesn't report its
  status to your terminal."
interactive-mode.md, *Vim editor mode*: "`←` on an empty prompt opens
  [agent view] from NORMAL mode as well as INSERT".
interactive-mode.md, keys: `Ctrl+C` — "If nothing is running, the first
  press clears the prompt input and a second press exits Claude Code";
  `Esc` + `Esc` — "When the prompt input contains text, double `Esc` clears
  it [...] When the input is empty, double `Esc` opens the rewind menu";
  `Ctrl+U` — "Delete from cursor to line start | Stores deleted text for
  pasting. Repeat to clear across lines in multiline input"; `Ctrl+E` —
  "Move cursor to end of current line".
CHANGELOG.md: 2.1.196 "Changed opening the agents view from a foreground
  session to require a single `←` press instead of two"; 2.1.290 "Changed
  the "Press ← again" confirm on a just-cleared prompt: a second ← no longer
  has to wait a second before it switches"; 2.1.162 "Fixed backgrounding a
  session with ← silently losing the conversation when the background
  service cannot start"; 2.1.141 "Empty idle background sessions left over
  from `←` are now automatically retired by the daemon after 5 minutes".

So `←` on an empty prompt does not open a picker inside the running
session: it moves the conversation into a new process under Claude Code's
background service and turns aineo's terminal into agent view, a list of
every background session across projects. What aineo's report tool, its
session hooks and its stop on quit (C3, C5, D36) do for a conversation
moved so was not measured.
