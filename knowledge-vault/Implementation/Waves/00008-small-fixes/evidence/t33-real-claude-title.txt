README.txt
----------

T33-6, the orchestrator's measurement of the real Claude Code's terminal title, run with the user's leave
(wave 8 decision T33-6 (a), "all recommended", 2026-10-06).

- Claude Code 2.1.292, started with no prompt in an already-trusted folder (the aineo checkout), so no
  trust dialog came up. It was given nothing, stopped by two Ctrl-C, and exited 0.
- Neovim 0.12.5, `nvim --clean --headless -l probe.lua`. The probe polls `b:term_title` every 50 ms and
  logs every OSC `TermRequest`.
- Three runs: out-plain.txt (no arguments), out-named.txt (`--name aineo-title-probe`) and
  out-disabled.txt (`CLAUDE_CODE_DISABLE_TERMINAL_TITLE=1`).

Findings:
- The title is set by OSC 0 about 0.9 s after start: "✳ Claude Code" with no name, "✳ <name>" with
  `--name`. The leading glyph is "✳" followed by a space.
- At exit the title is cleared: `b:term_title` reads "" afterwards.
- With CLAUDE_CODE_DISABLE_TERMINAL_TITLE set, see out-disabled.txt.
- Not measured: a title Claude Code generates during a turn, after `/rename`, after `--resume`, or the
  glyph while Claude is busy. Each needs a prompt to the real model, which this measurement does not send.

What it shows, for T33
----------------------

- With no name, the title is "✳ Claude Code"; with `--name <name>`, "✳ <name>". The glyph "✳" and
  one space precede the name.
- The title is cleared at exit: an empty title, which fires no `TermRequest` (none is logged at
  exit), so the clear is seen only as a change of `b:term_title`.
- With `CLAUDE_CODE_DISABLE_TERMINAL_TITLE` set, Claude Code sets no title at all: `b:term_title`
  holds the terminal buffer's own `term://` name from start to exit.
- Not measured: a generated title, `/rename`, `--resume`, and the glyph during a turn.
